# تجهيز مرحلة التشغيل اللاحقة

لم تنفذ الخطوات هنا في جولة تطوير المصدر. ابدأ على DB اختبار جديدة ومع بيانات اصطناعية، وراجع الترحيلات0011…0015 قبل تطبيقها. ملفات الهاكثون القديمة لا تعد شهادة جاهزية للامتداد.

1. أعد استخدام مفاتيح الجلسات الست المستقلة وعناوين الخدمات في إعداد المشروع الحالي. فعّل PH04…09 وحدودها و`KHOTWA_SYNTHETIC_DATA=true` للتجربة الداخلية فقط. `compose.beta.yaml` يمرر الآن الحدود الكاملة لهذه المزايا؛ الوصول يظل paused والمزود الخارجي معطلًا.
2. فعّل ACCOUNTS_ENABLED واضبط مفتاح OTP مستقلًا وallowlist حساب داخلي ومشرف. أضف `compose.mail-local.yaml` للتجربة المحلية؛ يلتقط SMTP الرسالة ولا يرسلها خارجًا. احمِ origin عبر إعداد HTTPS المشروع قبل الدخول؛ خصائص Secure/CSRF لا تُعطّل لأجل HTTP.
3. طبّق migrations بمالك DB الاختبار، ثم شغّل API بحساب DB محدود وفق `BETA-RUNBOOK.md`. إعدادات Compose لا تشغل migrations أو seed عند بدء API. لم تنشأ قاعدة بيانات من هذه الجولة.
4. افتح «إعداد المحتوى»، واستورد مصفوفات ملفات `apps/api/data/*draft.v1.json` تحت الغلاف `{ "items": [...] }` أو من مستورد الواجهة. راجع المحتوى والتلميحات ونتائج المحرك. للجبر انشر العلاج ثم النقل ثم الرئيسية من الدرس/المهارة نفسيهما؛ لا تعتمد المسودات تلقائيًا.
5. كتالوج الطالب يعرض الرئيسية فقط؛ مسار بداية الاستوديو ينشئ محاولة بإصدار المحتوى الصحيح. تلميحات وعلاج/نقل الجبر تظل في المسار الأصلي المراجع. الجلسة الافتراضية القديمة تبقى على بنك غير `studio-*` لتفادي خلط الإصدارات.
6. للفيزياء راجع المثال14m/s وتحويل km/h والخطأ14m. لتمارين Python جهز Runner معزولًا وافحصه أولًا وفق `runner/README.md`، ثم اضبط إعداداته على الخادم؛ غياب الخدمة يمنع النشر والتنفيذ الموثوق ويحفظ كود الطالب.

Reverse proxy يسمح حتى512KiB لاستيراد الاستوديو و64KiB لطلبات المنتج، فيما يحتفظ NestJS بحد4KiB للمسارات القديمة وحد64KiB للمنتج و512KiB للاستيراد فقط. هذا تنسيق لإعدادات المصدر، لا نتيجة فحص HTTP حي.

المتابعة: نفذ سيناريوهات التقارير السبعة، والسباقات والملكية والمحو واستعادة النسخة الاختبارية، وتأكد من مراجعة المحتوى والأجهزة والعزل قبل أي قبول تشغيلي. لا تفعّل AI أو SMTP خارجيًا أو نشر Beta أو بيانات حقيقية تلقائيًا.
