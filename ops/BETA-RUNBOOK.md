# تشغيل النسخة التجريبية المحدودة

هذه إعدادات جاهزة للمراجعة والتجربة اللاحقة، وليست إثبات نشر. لم يبدأ أي container أو خدمة بريد أو قاعدة بيانات أو Runner ضمن هذا التكليف. لا يوجد رابط Beta منشور أو مشاركون مسجلون من هذا العمل.

## الحسابات والبريد المحلي

1. جهّز مفاتيح البيئة الحالية المستقلة وأضف `ACCOUNTS_ENABLED=true` و`ACCOUNT_OTP_DIGEST_KEY` مستقلًا بطول ٤٣ محرفًا على الأقل. لا تضع أي قيمة سرية في Git. مدد الحساب المؤقتة قابلة للإعداد: OTP عشر دقائق، جلسة الحساب سبعة أيام؛ يلزم اعتماد خصوصية الاستخدام الفعلي قبل استقبال متعلمين حقيقيين.
2. راجع migrations `0011_accounts`…`0015_roadmap_retention`، ثم طبّقها في قاعدة اختبار جديدة ونسخة اختبار من بيانات قديمة. أمر التشغيل اللاحق من حزمة API هو `npx prisma migrate deploy --config apps/api/prisma.config.ts` مع `DATABASE_URL` لمالك قاعدة **الاختبار**؛ لم ينفذ هنا. لا تستخدم مستخدم migration في خدمة API.
3. للتجربة المحلية، استخدم إضافة `compose.mail-local.yaml`؛ خادم Mailpit يلتقط الرسائل محليًا ويعرضها على `http://127.0.0.1:8025` بعد تشغيله لاحقًا. لا يرسل بريدًا خارجيًا. وضع `ACCOUNT_MAIL_MODE=capture` مخصص للاختبارات الداخلية عبر حقن المزوّد، ولا يوفر مسار HTTP لقراءة الرموز.
4. تظل جلسة الضيف ممكنة. تسجيل الدخول لا ينقل المحاولات. لا يحصل الربط إلا بعد اختيار موافقة صريحة وإرسال `POST /api/v1/me/claim-guest` من المتصفح الذي يحمل الضيف الأصلي.
5. حدّد `ACCOUNT_INTERNAL_ALLOWLIST` للحسابات الاصطناعية الداخلية و`ACCOUNT_CONTENT_MANAGER_ALLOWLIST`/`ACCOUNT_ADMIN_ALLOWLIST` للتخصيص الأولي للأدوار عند التحقق لأول مرة. المتصفح لا يختار دوره، وتعديل دور قائم يستلزم إجراء تشغيل موثوقًا. لا تربط بيانات اصطناعية بحساب متعلم حقيقي.

`GET /api/v1/me` يعيد رمز CSRF للاستخدام الحالي و`loginCsrfToken` مستقلًا لعمليتي OTP. عمليات الكتابة تتطلب Origin مطابقًا وJSON وCSRF وIdempotency-Key. لا يُعاد رمز OTP أو cookie إلى JSON، ولا يُسجل في logs. البريد الحقيقي يتطلب SMTP عبر TLS ضمني؛ لا يُسمح باتصال plaintext إلا إلى Mailpit/loopback المصرح به محليًا.

## تجهيز Beta لاحقًا

انسخ قيم `ops/beta.env.example` إلى مخزن بيئة خاص خارج Git، وراجع `compose.beta.yaml` مع `compose.yaml`. يحتاج HTTPS إلى DNS ونطاق فعلي وشهادة Caddy؛ تشغيل ACME والنشر **لم ينفذا**. أبقِ `BETA_ACCESS_PAUSED=true` حتى تنتهي تجربة الاختبار. لا يدخل إلا بريد موجود في `BETA_EMAIL_ALLOWLIST`، بما في ذلك حساب المسؤول. إزالة البريد أو تعليق الحساب يرفض الوصول إلى الطلبات الجديدة، لا مجرد واجهة المستخدم.

قاعدة Beta لها volume مستقل ومستخدم owner للترحيلات، ومستخدم app بلا DDL أو صلاحيات superuser، ومستخدم backup للقراءة. ينشئ `ops/beta-init-db.sh` الأدوار على volume جديد فقط. لحساب الاحتفاظ، جهّز login مستقلًا وامنحه `khotwa_retention_operator` بعد تطبيق الترحيلات، مع `RETENTION_DATABASE_URL` خاص بالخدمة المجدولة؛ لا تمنح الدور إلى API أو حسابات البشر اليومية. لا تنشر منفذ PostgreSQL أو Python أو Runner للعامة.

`compose.beta.yaml` يجهز TLS على 80/443، ويترك واجهة التطوير 8080 مربوطة بـloopback. يجب مراجعة دمج ملفات Compose وإعدادات PH04…PH09 وحدودها قبل أي تشغيل. أوامر الصيانة تحت profile `maintenance` ولا تبدأ مع تشغيل التطبيق وحده.

## المتابعة والتكلفة

`GET /api/v1/beta/metrics` لمسؤول admin فقط. يعرض العدادات اليومية من DB، وآخر ١٠٠٠ زمن طلب للعامل الجاري منذ بدء التشغيل/بداية يوم UTC، وعدد 4xx/5xx، وtimeouts، ومصدر التلميحات، والاستهلاك المعروف للرموز. لا تظهر p50/p95 قبل ٢٠ عينة؛ لا تدعي العدادات معرفة عمليات عامل سابق بعد إعادة التشغيل. لا تحتوي المؤشرات على أسماء أو بريد أو نصوص محاولات أو prompts أو cookies. الملاحظات تُنقح من أنماط الأسرار الشائعة وتظل داخل صفحة المسؤول؛ التنقيح الآلي لا يعادل إذن إرسال أسرار.

الذكاء الخارجي مغلق افتراضيًا. تفعيله لاحقًا يحتاج الأذونات القائمة، وإعدادات المزود، و`BETA_AI_ENABLED=true`، وأسقف `BETA_AI_DAILY_COST_MICROS` و`BETA_AI_MONTHLY_COST_MICROS` و`BETA_AI_MAX_CALL_COST_MICROS` موجبة معلومة. الوحدات ميكرو دولار تقديرية إذا ثُبتت أسعار المزود؛ لا تحوّل وحدات الحصة التجريبية القديمة إلى سعر حقيقي. تحجز طبقة Beta الحد الأقصى المحافظ قبل الاستدعاء، بما في ذلك الفشل، وتوقف الاتصالات عند استنفاد السقف أو غياب تقدير السعر، مع fallback مراجع. توجد حدود مستقلة لطلبات/رموز الحساب اليومية. لا يُلغى سقف Gemini السابق ولا دفتر حصته.

`POST /api/v1/beta/access/revoke` يعلق الحساب المحدد ويبطل كل جلساته. لإيقاف الدخول للجميع اضبط `BETA_ACCESS_PAUSED=true` وأعد تشغيل خدمة API بالطريقة التشغيلية المعتمدة. لا تحذف volumes. لحالة صيانة طويلة، أوقف واجهة الدخول/خدمة API واحتفظ بقاعدة البيانات والنسخ المشفرة.

## النسخ والاستعادة والاحتفاظ

`tools/beta-backup.mjs` يستخدم `pg_dump` بصلاحيات قراءة، ويشفّر البث بـAES-256-GCM قبل حفظه. المفتاح `BACKUP_ENCRYPTION_KEY` يحوي ٣٢ بايت base64 ويُحفظ منفصلًا عن النسخة. لا تُكتب نسخة plaintext إلى القرص ولا يظهر URL/كلمة مرور في سطر الأمر أو السجل. حدد `BACKUP_DIRECTORY` خاصًا و`BACKUP_MAX_FILES` بين ١ و١٤. خدمة backup المجدولة تحفظ يوميًا العدد المحدود؛ `last-backup.json` يسجل التشغيل الفعلي و`restoreVerified:false` حتى توجد تجربة استعادة منفصلة.

تجربة الاستعادة المؤجلة:

1. أنشئ قاعدة **فارغة** مستقلة باسم `khotwa_beta_restore_<test>` مع مستخدم الاختبار فقط.
2. عيّن `RESTORE_TEST_DATABASE_URL` و`BACKUP_ENCRYPTION_KEY` في البيئة الآمنة، ثم نفذ لاحقًا `node tools/beta-restore.mjs --file=<encrypted-file> --confirm-test-only`. يرفض السكربت غير أسماء الاختبار المحددة، ويتحقق من مصادقة GCM بالكامل قبل إرسال أي dump إلى PostgreSQL، ويستخدم معاملة واحدة.
3. أعد تطبيق طلبات المحو وإبطال الجلسات اللاحقة للنسخة الاحتياطية من سجل التشغيل الموثوق، ثم افحص الحسابات والعزل والعينات قبل إتاحة نسخة الاستعادة. لا يجعل السكربت قاعدة الاستعادة عامة، ولا يدعي إعادة تطبيق tombstones تلقائيًا؛ يسجل `deletionTombstonesReplayed:false`.
4. شغّل رحلة اختبار على DB المستعادة وسجّل البصمة والنتيجة. لا توجد نتيجة استعادة حقيقية في هذا التسليم.

الاحتفاظ بالضيف يظل OWN-11: سبعة أيام بعد الانتهاء الفعلي. تتجنب الدالة حساب التعلم الدائم لحساب نشط، وتحذف أدلة المواد الجديدة وcache والملاحظات التابعة للملاك المؤهلين. التصدير خاص بالحساب وحده، مع حدود معلنة لعدد السجلات. `DELETE /api/v1/me` يسجل **طلب محو** ويوقف الوصول فورًا؛ لا يعرض «حُذفت بياناتك». استكمال محو الهوية والنسخ الاحتياطية يخضع لإجراء الخصوصية المعتمد وطلب المحو المسجل. مهمة الاحتفاظ القديمة تدعم الآن `--auth-cleanup` لتنظيف مواد المصادقة المنتهية عبر صلاحية صيانة مستقلة؛ الافتراضي dry-run، و`--apply` هو الاختيار الصريح للتنفيذ.

## برنامج الاختبار الثقيل المؤجل

لم يشغل ضمن هذا التكليف: إنشاء DB/ترقيتها، استعادة النسخ، DNS/TLS، SMTP فعلي، E2E، أو حمل. مرحلة التحقق التالية تشمل خمس رحلات: ضيف ثم حساب وربط؛ دخول من متصفح آخر؛ إنشاء/مراجعة/نشر محتوى؛ حل جبر/فيزياء وتلميح مع فشل المزود؛ تشغيل Python مع عزل Runner. أضف رفض الملكية وتكرار OTP والربط المتزامن وإبطال الحساب وطلب المحو والاحتفاظ على staging. قبل إشراك قُصّر أو متعلمين حقيقيين يجب اعتماد إشعار الخصوصية وسياسة الحساب والموافقات المطلوبة. لا تفعّل دفعًا أو دعوات خارجية أو نشرًا عامًا تلقائيًا.

التراجع إلى صورة تطبيق سابقة يتطلب توافق مخطط البيانات، وإبقاء revisions المنشورة وسجل الطلبات؛ لا تستخدم downgrade يحذف بيانات أو `docker compose down -v`. يمكن إعادة نشر إصدار محتوى أقدم مؤهل من لوحة المحتوى دون حذف محاولات الطلاب.
