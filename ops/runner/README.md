# Python Runner — إعداد مؤجل للتشغيل

هذا المشروع يوفر محول Judge0 CE خلف NestJS فقط. لا ينشئ خادم API عملية Python ولا يصل إلى Docker socket. المحول معطل افتراضيًا، وتبقى محاولة الطالب محفوظة عند غيابه. لا تعتبر اختبارات المحول المحاكية إثباتًا لعزل خادم فعلي.

قبل التفعيل، جهز Judge0 في بيئة مستقلة خاصة وفق تعليمات الإصدار الذي يراجعه مشغل الخادم، واضبط العزل الفعلي: حجب الشبكة، حدود CPU والذاكرة والعمليات والمخرجات، وعدم إتاحة ملفات المضيف أو بيانات اعتماد أو Docker socket لكود الطالب. يجب حجب خدمة Judge0 وقواعدها وواجهة Python عن الإنترنت. لا يوفر هذا المستودع Compose يزعم أن حاوية Python عادية sandbox؛ إعداد Judge0 الذي يحتاج صلاحيات للمشغل يتطلب مراجعة مستقلة قبل التشغيل.

بعد التحقق من البيئة ونسخة Python/LANGUAGE_ID، اضبط المتغيرات من `runner.env.example` في الخادم وحده. `RUNNER_ISOLATION_ATTESTED=true` تصريح تشغيل مطلوب من المشغل بعد الفحص، وليس نتيجة ينتجها الوكيل. لا تضع رمز الوصول في React أو Git. المهلة لكل تنفيذ وحد الموارد ترسل مع كل طلب، ويضاف حد يومي/دقيقة لكل مالك في PostgreSQL. نشر تمرين جديد يتطلب اجتياز الحل المرجعي لجميع الحالات عبر هذا المحول.

رحلة التحقق المؤجلة: شغّل مثال الطباعة ثم دالة الجمع، وحلًا بديلًا، وSyntaxError وRuntimeError وحلقة لا تنتهي، ثم محاولات ملفات المضيف والشبكة والذاكرة. أثبت فشل المحاولات الضارة داخل sandbox وبقاء API وDB سليمتين. افحص عدم ظهور الاختبارات المخفية في استجابة الطالب أو حزمة الويب، واستعادة كود الطالب بعد انقطاع Runner. لم ينفذ أي من ذلك في هذه الجولة.
