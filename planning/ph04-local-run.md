# تشغيل وفحص PH-04 محليًا

اختيار Prisma 7.10.1 مع SQL المكمّل معتمد من المالك في [DR-006](ph04-orm-decision.md). لا بيانات حقيقية أو نشر أو قبول بوابة في هذه التعليمات.

```powershell
npm ci --no-audit --no-fund
npm run verify:ph04
npm run verify:ph04:container
```

الأول يفحص العقود والتنسيق وlint والأنواع والبناء واختبارات API الخفيفة وsmoke التأسيسي. الثاني يبني صورتي api-test وapi، وينشئ شبكة Docker داخلية وقاعدة PostgreSQL 17.6 منفصلتين باسم عشوائي، دون منافذ host؛ بيانات PG في tmpfs مؤقتة فقط. ينفذ migrations ثم rollback صريحًا ثم replay والاختبارات الحقيقية، ويفحص صورة API بعد pruning بمستخدم غير جذري وroot filesystem للقراءة فقط، ويزيل موارده بعد حفظ الأدلة. لا يمس قاعدة Compose الأساسية. `--skip-build` متاح للتكرار المستهدف فقط إذا لم يتغير المصدر المترجم أو الاعتماديات، ويشترط وجود الصورتين من بناء حالي.

`apps/api/prisma/migrations` هو مصدر الترحيلات؛ `schema.prisma` يعكس البنية ويدعم client مضبوط الأنواع. القيود CHECK وDEFERRABLE وtriggers وview مكمّلة بـSQL؛ لا تستخدم `prisma db push` أو تقبل حذفها من diff آلي. migration 0002 يعالج حاجة Prisma لمفتاح مركب صريح لعلاقة current_version رغم تفرد id أصلًا. `qa/ph04-down.sql` مقصور على أداة الاختبار التي تتحقق من اسم/مضيف القاعدة المعزولة؛ ليس خطة rollback لبيانات منشورة.

كتالوج API يتطلب حزمة ومهارات ومسائل منشورة بعد مراجعتها. الترحيلات لا تضيف محتوى؛ fixture الاختبار موسومة `test_fixture_not_human_review` داخل القاعدة المؤقتة وحدها. الكتالوج فارغ دون نشر مراجع، وبدء learning-session يعيد 409 عند عدم وجود حزمة. مسائل العلاج والنقل والمسودة محجوبة من الكتالوج؛ فرع assignment لا يصدر إسنادًا قبل PH-08.

تشغيل API خارج الاختبار يتطلب أولًا migrations على قاعدة محلية مأذونة، وأصل HTTPS صالحًا وأسرارًا مستقلة وإعدادات محددة في `.env.example`، ثم `PH04_API_ENABLED=true`. `npm run env:local` يضيف الأسرار الناقصة فقط ولا يبدل الموجودة. علم التفعيل false في Compose التأسيسي حتى تهيئة هذه المتطلبات؛ لا تُعطّل Secure أو Origin أو CSRF لتشغيل HTTP. الاختبارات ترسل Origin صريحًا عبر عميل HTTP محلي وتفحص خصائص Cookie؛ لا تثبت متصفح HTTPS أو نشرًا عامًا. إعداد proxy/شهادة demo يخص PH-11.

حدود التجربة: bootstrap=120 ثانية، rate=1000 طلب/60 ثانية في عملية واحدة، timeout math=250ms في تكامل Mocks و1000ms في اختبارات adapter، وحجم استجابة math=64KiB، وحجم JSON عام=4KiB. هذه قيم اختبار وحدود محلية، وليست اعتماد سياسة أمن/أداء نهائية. قيم التشغيل الرقمية مطلوبة صراحة؛ لا تُستنتج من الإعدادات الصامتة. تحديد معدل الطلبات محلي للعملية ولا يستبدل مراجعة edge عند النشر.

عمر الضيف المطلق 24 ساعة والخمول ساعتان، وفق OWN-11؛ Cookie لا تخزن السر في JSON أو DB، وتظل HttpOnly/Secure/host-only/SameSite=Lax. التخزين يحفظ HMAC فقط، ويربط كل مورد بالمالك عبر NestJS. حذف الجلسة في API يبطل الرمز ويمسح Cookie؛ لا يدعي تطهير بيانات DB. جدولة التطهير بعد 7 أيام وآثار النسخ الاحتياطية لا تُفعّل أو تُختبر هنا؛ تبقى شرطًا قبل استخدام بيانات حقيقية.

تعديل أو حذف أو إضافة خطوة يرفع revision في transaction ويزيل completion القديم. الإبطال محافظ لكل نتائج الإصدار السابق، وinvalidatedFromPosition=1 لإعادة فحص السلسلة. current_verification_runs وrequireCurrentDependency بوابة النسخ للنتائج والمستهلكين اللاحقين؛ لا يعاد استعمال دليل قديم تلقائيًا. التشخيص والتلميحات والتقدم لم تُنفّذ في هذه المرحلة؛ يلزم ربطها بهذه البوابة عند بنائها. currentVerification يبقى null حتى PH-05.

MathGateway لا يتلقى AST من المتصفح، ويتحقق من المخططات والنسخ والسياق والمهلة وحجم الرد. الاختبارات تستعمل HTTP Mocks؛ لا تدعي تكامل الحكم الرياضي العام. AI معطل دون مزود أو اتصال خارجي؛ البديل الحالي تعذر مساعدة آمن لغياب قالب تربوي مراجع. لا توليد تلميحات أو اختيار مزود أو مخطط AI جديد قبل مرحلته واعتماده.
