# V2.2 / TASK-LP-01 — المواد والمسارات والوحدات والدروس

## الغاية
إنشاء مسار تعلم منظم **لا يكون مجرد قائمة أسئلة**: يستطيع الطالب فتح درس عربي فعلي يحتوي شرحًا وأمثلة متحققًا منها، ثم يبدأ تدريبه أو تقييمه.

## نموذج المحتوى المطلوب
```
Subject (الرياضيات)
  └── Track (الجبر الأساسي)
       └── Unit (وحدة)
            └── Lesson revision (درس بنسخة)
                 ├── objectives[] (أهداف تعلم)
                 ├── prerequisiteSkillCodes[] / prerequisiteLessonIds[]
                 ├── skillCodes[] (مصدر مهارات معتمد)
                 ├── contentBlocks[] (شرح، مثال خطوة بخطوة، تنبيه على خطأ شائع)
                 ├── practiceProblemRevisionIds[]
                 └── assessmentProblemRevisionIds[]
```
قبل إنشاء جدول: افحص الحقول المنظمة للوحدة/الدرس داخل `content-studio` و`ContentPayload` والجداول القائمة. إذا كفت، أضف فقط كيانات `learning_tracks` و`lesson_revisions` وروابطها؛ لا تكرر `subjects`, `skills`, `problem_revisions`. أسماء الجداول مقترحة ويجب تكييفها مع Prisma والمخطط الموجود.

## مهام البرمجة
1. أنشئ Track بترتيب وحدات ودروس واضح، عنوان/وصف/حالة نشر/إصدار. احتفظ بـstable ID وrevision؛ أرشفة لا حذف دائم للمحتوى المنشور.
2. دعم Content Blocks معروفة محدودة: `paragraph`, `heading`, `math_example`, `worked_steps`, `key_point`, `common_mistake`, `practice_link`، وجميعها عربية RTL. اجعل إدخالها وعرضها عبر مكونات آمنة، دون HTML خام غير منقح.
3. في `math_example` سجل نص المعادلة الخام والمعنى/العرض الموثق، والخطوات والحكم المرجعي (إذا كان مثال تحويل). راجع المثال عبر SymPy قبل النشر ولا ترسل الحكم إلى Gemini ليتخذه.
4. لا تُظهر دروس `draft` للطالب؛ فقط النسخ المنشورة، مع حفظ إصدار الدرس والمسألة الذي بدأ معه المتعلم.
5. أضف endpoints مناسبة للموجود، مثل `GET /learning/tracks?subject=math`, `GET /learning/tracks/:id`, `GET /learning/lessons/:id` (الأسماء قابلة للتكييف)، مع OpenAPI/DTO وملكية الأدوار.
6. وفر ملف محتوى أولي **مسودة** لمسار `الجبر الأساسي`: 
   - L01: المتغيرات والمعادلات البسيطة.
   - L02: توازن طرفي المعادلة.
   - L03: العمليات العكسية.
   - L04: توزيع الأقواس.
   - L05: الإشارات والمعامل السالب.
   - L06: معادلات متعددة الخطوات.
   اربط كل درس بالرموز القانونية الموجودة في `skills`، **لا تخترع رموز SK جديدة أو تربطها تخمينًا**؛ إذا غابت علاقة واضحة، وثق قرارًا معلّقًا.
7. يجب أن يحوي **درس توزيع الأقواس** على الأقل: هدف تعلم، شرحًا من 2–4 فقرات، مثالين محلولين خطوة بخطوة بعد تحقق رياضي، خطأ شائعًا، 2 سؤال تدريب من بنك منشور/مراجع، ورابط تقييم مستقل مختلف.

## الشروط المقبولة للتبسيط
- لا حاجة لمكتبة فيديو أو بث أو SCORM أو LTI أو بنية CMS خارجية.
- الدرس يمكن أن يُعرض كمحتوى عربي نصي منظم مع Math display الموجود.
- يمكن حفظ روابط الصور أو الفيديو لاحقًا لكن لا تجعلها شرطًا لنشر الدرس.
- لا تنشر الدروس الستة تلقائيًا إذا لم يعتمد محتواها؛ يكفي ملف draft ومثال درس واحد **إذا توفرت موافقة محتوى صريحة** للاختبار على بيئة محلية.

## الاختبارات المستهدفة
- الطالب يرى المسارات والدروس المنشورة فقط.
- درس منشور يعرض محتواه وأهدافه ومصادر أسئلته.
- تغيير درس منشور ينشئ revision ولا يغير سجلات جلسة قديمة.
- لا ينشر درس يحتوي مثال رياضي متناقض أو سؤال غير منشور.
- يمنع وصول طالب إلى مسودة المعلم.

**المخرج:** مسار جبر منظم، ودرس توزيع الأقواس مكتمل تربويًا في مسودة قابلة للاعتماد ومتصلة بأسئلة المراجع، مع ربط نسخة الدرس في سجل التعلم.
