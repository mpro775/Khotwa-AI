# V2.2 / TASK-LP-04 — رحلة الطالب في React

## الغاية
واجهة تعلم واضحة لا تتطلب من الطالب فهم أسماء المحركات التقنية. يجب أن يلاحظ القيمة الجديدة في أول استخدام: **أستطيع الدراسة، أو اختبار نفسي، أو علاج مهارة محددة**.

## صفحات/مكونات مطلوبة (ابنِ فوق ProductShell لا واجهة موازية)
1. **الصفحة التعليمية**: بطاقات مواد موجودة (الرياضيات/الفيزياء/البرمجة) مع حالة المحتوى. الرياضيات والجبر قابلان للاستخدام ضمن النطاق المراجع؛ الفيزياء/البرمجة يظهر لهما مسارهما المنشور فقط عند توفره، لا بيانات مزيفة.
2. **صفحة المسار**: عناوين الوحدات والدروس مرتبة، وصف موجز لكل درس، الهدف، المتطلبات السابقة، حالته `لم أبدأ/درست/تدربت/دليل فهم مستقل` مع روابط.
3. **صفحة الدرس**: شرح عربي منظم + مثال متحقق منه + «الخطأ الشائع» + زر «ابدأ التدريب» + «اختبر فهمي»؛ عرض المعادلة بالرمز س والأرقام والأقواس دون قلب المعنى. لا تجعل الفيديو شرطًا.
4. **وضع اختبر مستواك**: سؤال تلو الآخر، عدّاد تقدم، رسائل حفظ واضحة، بلا إظهار تلميح أو إجابة صحيحة أثناء القياس. عند طلب المساعدة يشرح النظام انتقاله إلى وضع التدريب.
5. **ملخص التشخيص**: عرض «ما نجحت فيه»، «ما يحتاج دليلًا إضافيًا»، «درس مقترح ولماذا»، مع خيار بدء الدرس أو تجاهل التوصية مؤقتًا. لا نسب إتقان غير مسندة.
6. **بعد الدرس**: مسائل تدريب وخيارات H1–H4 وفق المحرك الحالي، ثم سؤال مستقل مختلف. بعده تعرض النتيجة ومصدر التحقق والتطور مقارنةً بالمحاولات السابقة دون استخدام حكم نفسي دائم.
7. **التقدم الشخصي**: إن كانت الحسابات الفعلية جاهزة وخصوصيتها مختبرة، استخدم حساب الطالب؛ وإن بقيت `CODE-08` مفتوحة فلا تدّعِ الاستمرار عبر الأجهزة في الإصدار الجديد، واختبر بإعداد تجريبي اصطناعي فقط.

## ربط React بالـBackend
- استخدم API client/DTO القانونيين مع loading/empty/error states. لا تضع قاعدة اختيار الدرس في React؛ Backend هو مصدر التوصيات.
- حالة عدم كفاية البنك المنشور: «لا توجد أسئلة كافية لهذا التقييم بعد» مع زر الرجوع للدرس، لا بنود وهمية.
- احفظ المسودة الخام قبل الانتقال والتبديل، وألغِ الردود المتأخرة وأعد تحميل pinned revisions.
- اعمل على شاشة الكمبيوتر والهاتف متجاوبًا بقدر استغلال CSS الحالي، دون إعادة تصميم شاملة أو تطبيق أصلي. RTL للنص العربي وLTR لمحرر كود Python.
- aria-label وTab وfocus وتباين مناسب ورسائل status، وأزرار سهلة الوصول؛ لا تعاقب الطالب على `unsupported`.

## سيناريو تجربة المستخدم المطلوب (5 دقائق)
1. افتح الرياضيات ← مسار الجبر ← درس توزيع الأقواس؛ اقرأ المثال.
2. حل تدريبًا، اطلب تلميحًا وشاهد أن النتيجة «بمساعدة».
3. ابدأ تقييمًا قصيرًا مستقلًا؛ قدِّم خطوة غير مكافئة في توزيع الأقواس.
4. افتح ملخص الأدلة، واضغط الدرس الموصى به، واقرأ **سبب التوصية**.
5. أعد التدريب ثم حل سؤالًا مختلفًا دون مساعدة؛ شاهد تحديث التقدم المفسر.
6. أعد فتح الصفحة وتحقق من استمرار النسخة والمسودة حسب نوع الجلسة المسموح.

## شروط القبول
- لا أزرار شكلية: كل زر يفتح وظيفة حقيقية، أو يكون معطلًا وسببها معلنًا.
- كل شاشة تعرض البيانات من API أو حالة محلية مضبوطة؛ لا نسب تقدم hardcoded.
- لا تعرض حلول hidden أو أحكام Gemini على أنها حكم SymPy.
- لا تنكسر قراءة معادلات RTL الأساسية ولا تختلط الكسور المحجوبة بالمنشور.

**المخرج:** واجهة متصلة تجسد الحلقة التعليمية كاملة، لا مجرد تصميم Mock.
