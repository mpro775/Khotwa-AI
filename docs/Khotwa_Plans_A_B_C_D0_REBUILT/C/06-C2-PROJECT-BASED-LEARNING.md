# C2 — التعلم القائم على المشاريع Project-Based Learning

## ما يميز C2 عن C1
C1 يتمحور حول **سؤال/مشكلة** وحلها في نشاط؛ C2 يضيف **نتاجًا قابلا للتسليم**، ومعالم زمنية، ومراجعة وتحسينًا، وتكاملًا عبر مهارات متعددة، ومشاركة قرارات الطالب. لا تسمِّ كل مسألة «مشروعًا»؛ المشروع يقتضي مدة/مراحل/منتج موثق.

## التصميم التعليمي
- `drivingQuestion`: سؤال واقعي ذو معنى، أهداف مهارية قابلة للتحقق، متطلبات؛ نطاق متواضع في النسخة الأولى.
- `projectLevel`: `micro` (درس/مهارتان) ثم `multi_lesson` ثم `cross_subject` بعد تغطية الخريطة A4.
- `projectChoices`: خيارات سياق/شكل إنتاج محدودة، لا تغيّر كفايات التقييم الأساسية.
- `milestones`: تخطيط، بحث/نمذجة، تنفيذ، اختبار، مراجعة، تسليم، تأمل.
- `deliverableSpec`: وصف artifact؛ JSON/نص/رسم/ملف كود مع قيود؛ ليس رفع أي ملف بلا سياسة.
- `rubric`: معايير منشورة للطالب قبل العمل، أحكام خاصة للمراجعين، ومستويات أداء وصفية.
- `feedbackLoop`: مراجعة تكوينية ثم تعديل مع حفظ إصدارات، وعدم مسح ملاحظات سابقة.

## نسخ الإطلاق
**Micro:** مشروع جبر يختبر نموذج تكلفة ويرسم جدولًا؛ مشروع فيزياء يقيس/يحاكي حركة 1D؛ مشروع برمجة Parsons/خوارزمية موصوفة عند عدم تشغيل Python. **Multi-lesson:** يجمع مهارتين أو أكثر مع اختبار جديد. **Cross-subject:** نموذج حركة يتطلب معادلة فيزياء وتمثيلًا رياضيًا وتحليلًا برمجيًا؛ فقط بعد اعتماد ربط المهارات بين المواد ودقة المحركات.

## منهجيات مطبقة لا شعارات
سؤال محفز، تقصٍ مستمر بصورة تناسب المدى، أصالة، صوت الطالب/الاختيار، نقد ومراجعة، انعكاس، ومنتج عرضه ضمن نطاق آمن. لا نفرض «عرضًا عامًا على الإنترنت» على طالب صغير؛ يمكن عرض خاص للمعلم أو نموذج مستخدم افتراضي ثم نشر اختياري بموافقات إضافية مستقبلًا.

## حدود المرحلة الأولى
فردي فقط، لا فريق/تعليقات عامة/مشاركة للغرباء. لا plagiarism detector بالذكاء الاصطناعي بوصفه دليلًا حاسمًا، ولا auto-grade لمشروع مفتوح أو تنفيذ كود غير معزول.

## معايير القبول
يمكن للطالب بدء مشروع منشور، اختيار فرع مسموح، رؤية milestone/rubric قبل التقديم، حفظ نسخة تسليم، إرسال مراجعة، إدخال تعديل، وتسليم نهائي؛ ولا تعد حالة `completed` دليل إتقان إلا إذا خضعت المكونات لاختبارات مستقلة معتمدة.
