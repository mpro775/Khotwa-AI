# C4 — سير عمل التأليف والمراجعة والنشر

## الحفاظ على المصدر الموجود
استخدم حالات `draft` → `in_review` → `approved` → `published/archived` الموجودة في `learning-path-content.ts` مع revision counters وأقفال التزامن. إذا تعارضت الصلاحيات الفعلية، دوّن Gate بدل اختراع endpoint خاص يتجاوزها.

## واجبات المراجعين
- **مراجع المادة:** الأهداف، الأساس العلمي، صحة الأجوبة والبدائل والوحدات والمهارات؛ الرياضيات، الفيزياء، البرمجة كل حسب مجاله.
- **مراجع تربوي:** السؤال المحفز، التلميحات التدريجية، صلاحية Rubric، عدالة الأنماط، فصل التدريب عن التقييم.
- **مراجع الوصول/اللغة:** التمثيل البديل وRTL/LTR والهواتف/لوحة المفاتيح.
- **مراجع أمن عند artifacts/Runner/AI:** اختبار تسرب الحلول والثغرات وحدود الموارد.

## سلطة الموافقة
حاول فصل المؤلف والموافق النهائي حسب ما تسمح به صلاحيات النظام؛ لا تفترض أن وجود reviewer اسمي هو تدقيق بشري حقيقي. احتفظ `reviewerId`, `role`, `reviewedRevisionHash`, `scope`, `reviewDate`, `decision`.

## اختبار النشر
- publish مسودة بدون موافقة: رفض.
- publish مع reference مفقود أو غير منشور: رفض.
- نشر إصدار ثاني: يحتفظ طالب قديم بجلسة من v1، ويبقى v2 ظاهرًا للجدد وفق سياسة الإصدار.
- محاولة overwrite published payload: رفض؛ أنشئ revision جديدة.
- student GET لمسودة أو private rubric: 404 أو DTO منقح؛ لا IDOR.
- editor preview لا يضيف تقدمًا للطالب الحقيقي ولا يرسل Analytics حقيقية.
- rollback لا يحذف artifacts/نتائج pinned القديمة؛ يمكن تعطيل بدء جلسات جديدة.

## محتوى مبدئي مقترح للتجربة
سيناريو C1 واحد وخطة مشروع C2 واحدة ومجموعة C3 متكاملة لكل مادة **حيث يوجد محتوى علمي مراجع وبنك مستقل**. إذا لم يوجد بنك كافٍ، ابدأ بمراجعة fixture اصطناعي دون إعلان قبول تربوي.
