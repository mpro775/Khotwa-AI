# 23 — رحلة طالب قابلة للمراجعة (عربية) وChecklist يدوي

## سيناريو جبر C1
1. طالب افتراضي يفتح مسار جبر منشور، يرى موقف «مقارنة عرضي تكاليف» بدل تعليمات مسبقة «استخدم معادلة».
2. يكتب معطياته وافتراضاته ويحدد المجهول، ثم يجرّب جدولًا أو معادلة؛ تظهر نتيجة محققة في نطاق B1/SymPy فقط.
3. يطلب تلميحًا، ويخضع لتدريب بمساعدة. يعرض النظام بوضوح أن **المسألة لم تثبت إتقانًا مستقلاً**.
4. عند نهاية النشاط، يقترح اختبارًا جديدًا من عائلة غير مكشوفة إذا وُجد بنك مراجع؛ وإلا رسالة «لا يوجد تقييم مستقل مؤهل بعد».
5. يعرض في C5 «حللت مشكلة بتوجيه» منفصلًا عن أدلة نجاحك في اختبار مستقل.

## سيناريو فيزياء C1+C3
1. سؤال أصيل عن حركة خطية مع توقّف، يطلب توقع الزمن/المسافة والافتراضات.
2. يمكن فتح وصف نصي/جدول قبل محاكاة B2، ويظهر disabled مع تفسير عند إغلاق العلم.
3. يسجل توقعًا قبل الكشف، ثم يعدل المتغيرات ويشرح الفرق والوحدة.
4. بدون حركة رسومية أو على هاتف، تتاح جداول ونصوص قابلة للقراءة بدون عقوبة.

## سيناريو برمجة C2
1. يبدأ مشروع «برنامج حساب أجرة بسيطة» مع milestones: فهم، تصميم flow، Parsons/trace، اختبار حالات يدوية، عرض تفسير.
2. نص Python لا يعمل خارج Runner؛ تظهر عبارة «تقييم منطقي/تتبع دون تنفيذ كود» بوضوح.
3. يسلم ملف نص/JSON محدودًا، يتلقى rubric feedback في حساب مخول، ثم يعدل ويسلم نسخة نهائية.
4. النتيجة المعروضة «مشروع مكتمل ومراجع»، لا «أتقنت البرمجة» ما لم توجد مهمة مستقلة موثوقة.

## أسئلة قبول يدوي للمراجع
- هل فهم الطالب السؤال دون معرفة القانون مسبقًا؟ وهل يمكنه الرجوع لمتطلبات سابقة دون ضياع الجلسة؟
- هل كل صفحة تدعم القارئ/لوحة المفاتيح والتكبير والاتجاه العربي مع الرموز؟
- هل المعلومة الخاصة بالحل والتقييم تبقى مخفية قبل وقت الكشف، حتى في network developer tools؟
- هل تظهر حالات النظام بصدق: تحتاج مراجعة / غير مقاس / الخدمة لا تعمل؟
- هل reviewer يرى provenance والنسخة والمعيار ولا يستطيع رؤية أعمال غيره دون صلاحية؟
- هل أثبتت لوحة الطالب أن «وقت النشاط» و«مشروع مكتمل» ليسا درجة إتقان؟

## تسليم دليل
لقطات مختصرة بعد موافقة/إمكان تشغيل بيئة اصطناعية، سجلات أحداث منقحة، نسب التغطية وقائمة قضايا، جهاز/متصفح/تاريخ وإصدار. إن منع التشغيل بعائق فلا تُنشئ صورًا وهمية أو نتائج تلقائية.
