## 2. ما تم التحقق منه مباشرة أثناء التدقيق

- وجود الملفات المصدرية: `apps/api/src/advanced-learning/{workflows,workflow-state,activity-payload,analytics-service,analytics-projection}.ts` ومكونات الويب `ProblemJourney.tsx`, `ProjectWorkspace.tsx`, `AdvancedContentStudio.tsx`, `LearningAnalyticsDashboard.tsx`، والهجرة `0025_advanced_learning_c`.
- الأعلام في `.env.example` مغلقة افتراضيًا، بما فيها `REAL_LEARNING_ENABLED=false` وسبعة أعلام C، إضافة إلى جسر Runner وPhET.
- **بوابة حقيقية تحتاج تطويرًا لا مجرد إعداد:** `apps/api/src/intelligent-learning-data.ts`, `authorizeA()` تشترط `store.syntheticData` وتمنع الحسابات غير الداخلية لكل A/B/C. `apps/api/src/learning-path-content.ts` يستلزم بيانات اصطناعية ومراجعات `TEST_ONLY` لأنشطة C. لا يجوز إلغاء هذه الحراسات دون تصميم بوابة إطلاق مُعتمدة واختبارات أمن وملكية.
- اختبار CRC للأرشيف `Khotwa-AI-main (1).zip`: ناجح، 1231 مدخلاً. بصمات تقارير `C-TESTS.json`, `C-INTEGRATION.json`, `B-REGRESSION.json` مطابقة لملف `C-RELEASE-CANDIDATE.json`.
- **انحراف في سجل مرشح الإصدار:** من 99 ملفًا في manifest تطابقت 96، واختلفت بصمات `.env.example`, `AGENTS.md`, `README.md`. هذا لا يثبت فسادًا أو خطأ سلوكيًا، لكنه يمنع اعتماد بصمة الإصدار بصورتها الحالية قبل تفسير الفروق وتجديد البيان.
- سجلات A/B/C تشير إلى عمل في working tree دون `commit/push/deploy`. ZIP لا يحتوي `.git`، لذا تحقق من `git status`, `HEAD`, ونظافة الفرع في نسخة الوكيل قبل اعتماد التجميد.

## 4. التسلسل الموصى به

### STEP 0 — تجميد الكود والتحقق من سلامة التسليم

1. على جهاز الوكيل: `git status`، تأكيد كل تغييرات A/B/C، commit/branch مع اعتماد المالك، مراجعة سبب اختلاف بصمات الملفات الثلاثة، وإعادة إصدار manifest على الحالة النهائية.
2. إعادة فحوص A/B/C الموجهة والعقود والإصدارات على نفس commit المجمد، دون تعديل Golden لإخفاء حالات معلقة.
3. توثيق Scope `SOURCE_COMPLETE` مقابل `RELEASE_BLOCKED` وفتح تذاكر بالمالكين.

### STEP 1 — اعتماد علمي ومحتوى تجريبي صغير

1. حسم تشخيص الجبر وربط المهارات مع مختص الرياضيات وQA.
2. اعتماد وحدة جبر واحدة كاملة **كنموذج** قبل تعميمها: نشر دروسها المراجعة وربط تقييم مستقل فعلي وبنك غير مكشوف وتلميحات وتدرج وتكرار متباعد، إضافة إلى مشكلة ومشروع متناسبين.
3. تجهيز موضوع حركة خطية واحد ودرس Python قراءة/Parsons للتجارب المنضبطة مع مراجعين متخصصين؛ لا ادعاء قياس برمجي مستقل دون Runner.

### STEP 2 — قبول تفاعلي وأمني

1. تشغيل staging synthetic على مصدر مجمّد، وتجربة رحلات الطالب والمؤلف والمراجع عبر Chrome فعلي لا SSR فقط؛ ثم الهاتف والتكبير والقارئ والشبكة المتقطعة.
2. اختبار مراجعة النسخ والملكية وعدم التسريب وclaim/export/delete/purge وتعطل الخدمة/استئناف المسودة؛ معالجة الأعطال وتصحيح التقارير.
3. تصميم قناة real-learning منفصلة ومأمونة بدل تعطيل الحارس الاصطناعي، بعد موافقات السياسات والتدقيق الأمني.

### STEP 3 — إطلاق تجريبي حقيقي ضيق بعد الموافقات

1. Staging من نسخة قاعدة قائمة إن وجدت؛ backup/restore وmigration 0023/24/25 مع تسجيل النتائج.
2. تجربة أولية مغلقة ومراقبة للدرس/الوحدة المعتمدين فقط، بحدود واضحة للطلاب والمحتوى والميزات؛ يمكن ترك Gemini/Runner/PhET/cohort/uploads مغلقة.
3. قياس مستقل قبل/بعد ثم delayed retention، ومؤشرات C5 مع المقامات الصحيحة؛ مراقبة الأعطال والخصوصية والتكلفة؛ قرار التوسع قائم على نتائج لا على شعور الاستخدام.

### STEP 4 — التوسع بعد الإثبات

- توسيع محتوى الفيزياء والبرمجة والمشاريع متعددة الدروس، ثم ربط المواد المختلفة إن كانت الخريطة والتقييم يدعمانه.
- فتح Python Runner فقط بعد اختبار معزول للشبكة/الملفات/الموارد والتنفيذ المتزامن؛ PhET فقط بشروط استعمال صحيحة.
- لوحات teacher/cohort فقط بعد علاقة وصلاحيات وموافقة خصوصية وعتبات تجميع معتمدة.
- تحسين الأداء/حجم JavaScript واختبارات الحمل والمراقبة والنسخ الاحتياطية.

## 5. ما لا ينبغي أن يفعله الوكيل في هذه الجولة

لا ينشئ D1/D2 بميزات إضافية قبل غلق D0؛ لا يشغّل قاعدتك الحالية أو يطبق migrations عليها دون إذن؛ لا يغير `syntheticData` أو `is_internal` أو `TEST_ONLY` بغرض فتح الإنتاج؛ لا يفعّل Runner/PhET/Gemini/analytics cohorts بمجرد flag؛ لا يختلق توقيعات مراجعين أو نتائج قياس بشرية؛ لا يعد نجاح C اختبارات إتاحة فعلية؛ لا يغير Golden صامتًا لتصفير إخفاق مراجع البيانات.

## 6. قرار المنتج المقترح الآن

**ابدأ بوابة D0: Source Freeze + Domain Review + Manual Acceptance + Safe Real Release Design**، ولا تبدأ سلسلة تعليمية جديدة D أو المزيد من ميزات المنصة قبل التحقق من المسار الفعلي لطالب واحد في وحدة جبر مكتملة مع مراجعات واعتمادات واضحة.

**ملخص:** A/B/C موجودة تقنيًا؛ العائق الحقيقي التالي هو جاهزية الطالب/المحتوى/التشغيل. لا يمكن استخلاص نسبة جاهزية إنتاج من عدد المراحل المنفذة.
