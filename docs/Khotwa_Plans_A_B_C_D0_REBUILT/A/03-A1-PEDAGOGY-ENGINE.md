# A1 — Pedagogy Engine | محرك القرار التعليمي

**الأولوية:** P0 لهذا البرنامج. **يعتمد على:** مصدر V2.2، ويقدم نقاط التوسعة لـA2/A3/A4/A5/A6/A7/A8 لاحقًا. **لا يلغى** `recommendLesson()` الحالي.

## رحلة الطالب المطلوبة

بعد اختبار قصير أو حل سؤال أو دخول درس، يظهر نشاط واحد مقترح مع «لماذا الآن؟»، وبدائل ممكنة. قد يكون النشاط: شرح قصير، مثال محلول، سؤال تشخيص، تدريب موجه، إصلاح مقدمة، مراجعة مستحقة، فحص مستقل، تحدٍّ، تأمل في طريقة الحل. لا يجبر النظام الطالب دائمًا على تسلسل خطي؛ اختيار نشاط آخر مسموح ضمن سلامة القياس.

## العقود السلوكية

`ActivityKind = explanation | worked_example | diagnostic_probe | guided_practice | prerequisite_repair | independent_check | retrieval_review | challenge | reflection`.

| شرط مرصود | قرار ابتدائي مقترح | لماذا |
|---|---|---|
| لا أدلة كافية أو مهارة جديدة | شرح أو مثال منشور، أو اختبار قبلي إن كان بنك مستقل كافيًا | لا نسمي غياب الأدلة ضعفًا |
| خطأ مستقل متحقق + فرضيتان معقولتان | diagnostic_probe منشور | نجمع دليلًا بدل الجزم بسبب |
| خطأ في متطلب أساسي موثوق ودرس متطلب منشور | prerequisite_repair | نعالج الأصل قبل الصعوبة التالية |
| مراجعة سابقة مستحقة وبنك جديد | retrieval_review | نختبر الاحتفاظ بدل إعادة قراءة فقط |
| صحة مع اعتماد على التلميحات | guided_practice بسقف دعم أقل أو worked step ناقص | فصل الدعم عن الاستقلال |
| نجاح مستقل حديث فقط | independent_check أو challenge مناسب | نتحقق من التنوع والتطبيق دون ادعاء إتقان ثابت |
| تعذر المحرك / unsupported | explanation محايد أو no_safe_activity | لا نصنع دليل فشل مفاهيمي |
| لا نشاط منشور آمن أو نقص بنك | no_safe_activity + سبب + بدائل قراءة إن وجدت | لا نسرب أسئلة ولا ننشر draft |

**حل تعارض القواعد:** حماية القياس والمحتوى/الملكية أعلى من أي أولوية تربوية؛ ثم النشاط المستحق والمحتمل تأثيره، مع ترتيب حتمي وتعادل مستقر. يُمنع تكرار نشاط واحد على نحو مرهق عبر cooldown محدود موثق، دون تعديل نتيجة الطالب. عتبات «تكرار الخطأ» و«عدد أنشطة» إعدادات versioned قابلة للمراجعة وليست حقائق علمية.

## مهام البرمجة

1. استخراج مصدر السياق من `LearningAssessmentService.progress/summary`, skill-map، content revisions، exposures. لا تستبدل أحكام V2.2.
2. إنشاء `PedagogyPolicy` نقية قابلة للوحدة مع `eligibleCandidates()` و`decide()` و`fallback()` وسبب رفض كل مرشح.
3. تصميم حدث قرار مؤرخ ومرتبط بالمالك/المسار/نسخة الأدلة ونسخة السياسة؛ منع التسريب عبر DTO عام محدود.
4. إضافة GET مقترح `/api/v1/learning/next-activity?trackRevisionId=...` وPOST مقترح `/api/v1/learning/activities/accept` بعد مراجعة العقد. إدخال idempotency و optimistic revision.
5. تعديل React لبطاقة النشاط التالي وشرح «سبب محتمل/المعطيات محدودة» وإجراء «ابدأ» وبدائل مؤهلة، والرجوع لمنظومة V2.2 عند flag off.
6. إضافة feature flag مستقل `PEDAGOGY_ENGINE_ENABLED` = false افتراضيًا في البيئات غير الاختبارية، مع تسجيل policyVersion.

## اختبارات قبول المرحلة

- [ ] قرار حتمي لنفس snapshot؛ نتائج مختلفة عند تغيّر evidenceRevision؛ القرار القديم يرفض 409 وليس silent accept.
- [ ] تدخل بعد خطأ متحقق؛ لا تشخيص جازم من خطوة واحدة.
- [ ] service_error وsyntax_error لا ينتجان `needs_review` جديدًا.
- [ ] لا يسمح اختيار lesson draft أو problem exposed للقياس، حتى لو طلبت الواجهة ID مباشرة.
- [ ] عند نقص المحتوى يُعرض no_safe_activity بوضوح، لا حل مخفي ولا fallback خارج الموضوع.
- [ ] `GET /recommendations/next` والعقود السابقة تظل تعمل ونتائجها قابلة للتفسير.
- [ ] طالب ب لا يستطيع قبول قرار طالب أ؛ double-click ينتج نشاطًا واحدًا فقط.
- [ ] الاختبار على Algebra وPhysics، وProgramming يبقى read-only حيث يتطلب Runner.

**مخرج A1:** تقرير `qa-reports/A1-PEDAGOGY-ENGINE.md` مع مصفوفة قرارات من 10+ حالات اصطناعية، عينات الردود، ونتائج الاختبارات والحدود، ثم استكمال A2 دون انتظار نشر إنتاجي.
