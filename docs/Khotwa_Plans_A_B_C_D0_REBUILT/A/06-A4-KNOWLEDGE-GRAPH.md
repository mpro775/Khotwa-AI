# A4 — Knowledge Graph | خريطة المعرفة والمتطلبات

**الهدف:** معرفة **من أين يبدأ إصلاح الفجوة** عبر المهارات وأحيانًا عبر المواد، بدل إعادة الدرس الذي توقف فيه الطالب دون تحديد جذور محتملة. يستثمر `skills` و`skill_prerequisites` و`LearningSkillMap` الحالية.

## النموذج المقترح

| الكيان | البيانات | شروطه |
|---|---|---|
| Skill node | `skillCode`, `subjectCode`, `releaseId`, Arabic title, status, curriculum scope | مفتاح مستقر داخل revision؛ لا تضف مهارة غير معتمدة صامتًا |
| Prerequisite edge | `fromSkill`, `toSkill`, `relationKind: required | helpful | cross_subject_support`, rationaleAr, review state/version | `required` يخضع لقيود gating؛ `helpful` توصية فقط |
| Content coverage | `skillCode → lessonRevisionId/problemRevisionId`, coverage kind, review state | يشير إلى **نسخة منشورة** فقط في سطح الطالب |
| Graph revision | contentRelease/revision, hash, reviewer identity/approval, createdAt | لقطات قابلة للتتبع لا تعديل صامت لتاريخ الطلاب |

استخدم جدول `skill_prerequisites` الموجود وحقل `prerequisiteSkillCodes` في payload أولًا. إذا لزم إضافة العلاقات العابرة للمواد أو حالة مراجعة الحافة، أضف امتدادًا **متوافقًا** مع مصادر الحقيقة بدل نسخ نفس حواف المتطلبات في جدولين متعارضين.

## قواعد الاستعلام واتخاذ القرار

1. `getPrerequisiteClosure(skillCode, contextRelease)` يعيد أقرب متطلبات صالحة مع depth محدود وترتيب مستقر وأسباب.
2. لا حواف دائرية في graph المنشور؛ تحقق من DAG أو فصل أنواع الحواف غير الإلزامية. تقرير validation يسمي مسار الدورة.
3. لا يكفي ضعف التقدم في درس ما لتشخيص متطلب لم يختبر بعد. رتب الجذور بحسب **أدلة مستقلة** أو اقترح probe إذا كانت الأدلة غير كافية.
4. الحواف العابرة للمادة تستخدم مهارات معرّفة في نطاقها وتحتاج مراجعة مختصين؛ مثال: `الجبر: حل معادلة خطية` قد يكون متطلب دعم لدرس `فيزياء: السرعة والتسارع` عند تضمنه معادلات. **لا تُفرض حافة مثال تلقائيًا دون مراجعة منهجية**.
5. `mappingPending` يمنع استخدام الحافة/الدرس في توصية علاج حاسمة أو نشر المسار، لكنه لا يحجب قراءة الدروس المنشورة الأخرى.
6. عند إصدار جديد للخريطة، الجلسات القائمة تظل متتبعة بمخططها المثبت، وتصدر توصيات جديدة من نسخة متوافقة أو تطلب تجديد السياق صراحة.

## مهام التنفيذ

- كتابة `graph-validate` وخدمة قراءة/ربط، وواجهة معلم أو وحدة PathStudio لرؤية الحواف وأسبابها وحالة المراجعة.
- توسيع `GET /api/v1/learning/skill-map` بصورة متوافقة أو إضافة `GET /api/v1/learning/knowledge-graph` (العقد يقرره تدقيق A). لا تكشف drafts عبر endpoint العام.
- إضافة `GET /api/v1/learning/prerequisites?skillCode=...` اختياريًا إذا تجنب التعقيد، وتوثيق التصادم إن وجد.
- اختبار SK-ALG-03 الذي يرد مهارة ثانوية في `ALG-L06`: لا تختلق درسًا أساسيًا أو تلقائيًا؛ تقارير الفجوة توضح عدم وجود درس primary معتمد.
- تعديل A1 لتمييز `prerequisite_repair` عن `diagnostic_probe` وبناء سبب تفسير.

## اختبارات قبول

- [ ] Graph صالح مع متطلبات داخل المادة وعدم تضارب الإصدار.
- [ ] دورة `A→B→A` تمنع نشر revision وتعرض الحواف المتسببة دون تخريب النسخة المنشورة.
- [ ] مهارة بلا درس منشور لا تقود إلى رابط draft ولا إلى صفحة 404 متوقعة.
- [ ] اختلاف `required` عن `helpful` في القرار؛ حالة الطالب `not_assessed` لا تُفسّر كفشل.
- [ ] حافة بين الجبر والفيزياء لا تعمل كمتطلب ملزم ما لم تكن reviewed.
- [ ] تتبع session قديمة يظل مربوطًا بـmapping snapshot، بعد تعديل graph.
- [ ] لا كشف دروس/معرفات مسودات في API الطالب.

**مخرج A4:** تقرير مراجعة graph يتضمن عدد الحواف المراجعة والمعلقة، دورات مرفوضة، وروابط محتوى ناقصة دون اختلاق اعتماد.
