# KHOTWA AI — حزمة مختبرات STEM التخصصية B1–B3 | START HERE

**الحالة:** مواصفات تطوير مستقبلية للتنفيذ البرمجي، وليست تقريرًا بأن المختبرات منفذة.  
**تاريخ مرجع المصدر:** 2026-11-08، حزمة `Khotwa-AI-codex-v2.2-learning-paths (1).zip`.  
**النطاق المفوض:** B1 مختبر الرياضيات، B2 مختبر الفيزياء، B3 مختبر التفكير البرمجي + التكامل المحدد مع خطة A1–A8. **لا تنفذ C1–C7 ولا نشرًا إنتاجيًا.**

## الرؤية

المحرك المشترك يقرر *متى* يحتاج الطالب نشاطًا ولماذا؛ المختبر التخصصي يحدد *ماذا يفعل* الطالب وكيف يُتحقق من النتيجة. التجربة المطلوبة: **لاحظ/توقع → جرّب أو حل → فسّر → تحقق مستقل جديد → تراجع عن الخطأ عند الحاجة**. لا تفرض هذه الدورة حرفيًا على كل درس؛ ضع استراتيجية تناسب كل مهارة ومستوى.

| المسار | أهم قدرات التسليم | القيد الأساسي |
|---|---|---|
| B1 — الرياضيات | ربط المعادلة والجدول والرسم، المقارنة بين طرق الحل، رصد أول انتقال غير مكافئ، أسئلة «لماذا؟» | حكم رياضي موثوق من Python/SymPy في النطاق المعتمد، لا من JS أو LLM |
| B2 — الفيزياء | توقع → تجربة بارامترية → ملاحظة → تفسير → مسألة قياس منفصلة | نماذج 1D معرّفة ومراجعة علميًا؛ لا توهم بوجود مختبر عام لجميع الظواهر |
| B3 — البرمجة | توقع المخرجات، تتبع التنفيذ، Parsons، تشخيص خطأ، كتابة كود واختباره عند السماح | الأنشطة غير التنفيذية أولًا؛ لا تشغيل لكود غير موثوق قبل اعتماد Runner معزول |

## ثوابت ملزمة

- **لا تفترض** أن A1–A8 قد دخلت أحدث السورس؛ هي خطة مستقلة، ومقترحاتها ليست API حاليًا. إذا نُفذت، استخدم عقودها الفعلية. إذا لم تنفذ، أنجز المختبرات خلف feature flags ووثّق تكاملًا مؤجلًا دون API موازٍ.
- V2.2 يستخدم **NestJS + PostgreSQL/Prisma + React**، ومحرك Python/SymPy، ومتحقق الفيزياء، وJudge0 Runner خاص اختياري. لا تبدل المكدس ولا تُدخِل MongoDB أو Firebase هنا.
- لا تعدّل Golden أو مجموعة الأخطاء أو نطاق التحقق الرياضي لتبدو التجربة ناجحة. `SK-ALG-08` والكسور والدوال المثلثية خارج نطاق الجبر الحالي؛ لا تدّعِ دعمها.
- لا تجعل تغيير منزلق/رسم/مشاهدة مثال أو محاكاة أو قراءة أثر كود نجاحًا مستقلًا. فصل **الأنشطة التعليمية** عن **القياس المغلق الجديد**.
- المحتوى المراجع والمُنشور فقط يظهر للمتعلمين؛ كل درس/نشاط/سؤال له revision مثبت؛ لا تُنشر مسودات لأن build ناجح.
- لا تضع API خاص بتجارب المختبرات في متصفح عام للوثائق دون auth/ownership، ولا تعرض hidden tests أو حلول القياس في DTO.
- أي نشر لمحاكيات PhET في منتج تجاري **معلّق ببوابة الترخيص**؛ راجع `08-B2-PHET-LICENSE-AND-FALLBACK.md`.
- **لا تنفذ migrations على إنتاج، ولا تنشر، ولا تشغّل Gemini أو Judge0 أو خدمات مدفوعة أو تشغيل كود طالب على جهاز المضيف دون إذن منفصل.** يسمح بالاختبارات المحلية الموجهة، build، lint، mocks للمحاكيات غير التنفيذية، وتوثيق المتعذر.

## تعريف «مكتمل» لهذه الحزمة

كل مختبر يملك نشاطًا موضوعيًا مؤلفًا ومراجعًا وقابلًا للتنفيذ أو تجربة محلية آمنة، حدثًا تعليميًا قابلًا للتتبع، قياسًا مستقلًا **بمهمة مختلفة** عند توفر بنك مناسب، UI عربية RTL متاحة، واختبارات حقيقية بلا claims زائفة. لا تُسمِّ المختبر «جاهزًا للطلاب الحقيقيين» قبل المراجعة العلمية، وبيانات الأمان، وتجربة فعلية على الأجهزة.
