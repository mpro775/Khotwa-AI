# 10 — B3 | مختبر التفكير البرمجي — مواصفات المنتج

**الهدف:** تعليم التفكير الخوارزمي، والتنبؤ، والتتبع، وإصلاح الأخطاء، ثم كتابة الكود والتحقق منه. لا نريد تحويل الذكاء الاصطناعي إلى مولّد حلول يكتب الواجب بدل الطالب.

## 1. أنواع الأنشطة المطلوبة

| ID | النوع | ماذا يتعلم الطالب | الحاجة إلى تنفيذ كود غير موثوق؟ |
|---|---|---|---|
| B3-01 | `predict_output` | قراءة الكود والتنبؤ بالمخرجات والمتغيرات | لا؛ answerKey راجعه مؤلف أو oracle مختبر بأمان |
| B3-02 | `code_trace` | تتبع خطوات قليلة وتحديث state | لا؛ trace snapshot معتمد ومحدود |
| B3-03 | `parsons_reorder` | إعادة ترتيب أسطر مفككة للوصول إلى برنامج صحيح | لا؛ grading against reviewed constraints |
| B3-04 | `debug_select_fix` | تحديد خطأ منطقي/نحوي/تشغيلي وشرح أثره | لا في النسخة الأولى؛ اختر من إصلاحات مراجعة |
| B3-05 | `write_and_run` | كتابة كود واختبار public cases | **نعم؛ Gate-R إلزامية** |
| B3-06 | `submit_independent` | حل مستقل بتقييم hidden/public cases | **نعم؛ Gate-R + novelty + no hints** |

ابدأ بالأنشطة B3-01…B3-04 بحيث يعمل المختبر بصورة مفيدة حتى وRunner متوقف. لا تخلق Interpreter «Python شبه كامل» في المتصفح وتعلن أنه حكم رسمي.

## 2. مسار تعلم Python أولي

`PY-PRINT` → `PY-VARIABLES` → `PY-ARITHMETIC` → `PY-CONDITIONS` → `PY-LOOPS` → `PY-FUNCTIONS`، وفق مهارات المصدر، مع التحقق من روابط A4 إن أُنجزت. **أمثلة الأنشطة:**

- المتغيرات: يتوقع قيمة `x` بعد assignment ثم `print(x)`.
- الحلقات: جدول iteration `n`, `total` وتوقع الناتج النهائي؛ البنية تقود خطأ off-by-one.
- الشروط: يرتب branches ويُفرق بين equality وassignment في الأسئلة المدعومة.
- الدوال: Parsons لأسطر تعريف دالة بسيطة وتوقع return value قبل التنفيذ.

هذه أمثلة `curriculum seeds` تحتاج مراجعة خبير برمجة قبل النشر، وليست جميع دروس Python الحالية مكتملة.

## 3. واجهة الطالب

- كود Python مع `dir="ltr"` وخط monospace وأرقام أسطر؛ التفسير والأزرار بالعربية RTL.
- سؤال «ما الذي سيحدث قبل أن تضغط تشغيل؟»، ثم حالة step/trace عند التحقق.
- بعد خطأ، اسأل عن أول اختلاف متوقع بين الحالة والتتبع؛ لا تُظهر الحل كاملًا مباشرة.
- يدعم Parsons اختيارات بلوحة المفاتيح (أزرار أعلى/أسفل)، وليس drag-only؛ لمستخدم قارئ الشاشة ترتيب السطور محفوظ في aria labels.
- عند runner unavailable زر «جرّب برنامجك» معطل بوضوح، لكن أنشطة tracing/parsons تعمل بلا runner.

## 4. الالتزام بالاختبار المستقل

- `B3-01..04` تقدم أدلة أداء **معيارية محدودة** إذا وُجدت keys مراجعة وتحقق، لكنها ليست تلقائيًا «استطاع كتابة برنامج حقيقي»؛ صنّف نوع الدليل `conceptual_practice`.
- `run` تجربة بمساعدة/اختبارات علنية، لا يحتسب نجاح مستقل حتى لو مرّت كل الحالات.
- `submit` في runner مؤهل وبدون تعرض مخفي، وبعد كشف مصادر الدعم وفق A6/A7، يدخل قناة Evidence فقط إذا تحقق اختيار سؤال جديد، no hints، نتائج مؤهلة، وcompatibility مع السياسة.
- لا تعرض hidden tests وexpectedOutput الخاص بها إلى الطالب أو نص prompt أو سياسة LLM.

## 5. تسليم B3

نشاط tracing + Parsons + debugging يعمل محليًا دون Runner، ووصلة محكومة إلى `ProgrammingService` الموجودة لا تُفعل إلا مع sandbox attestation، مع أنواع الدروس واستوديو authoring وQA. التقرير `qa-reports/B3-CODING-LAB.md` يفصل `NON_EXECUTING_PASS` عن `RUNNER_ENABLED_PASS` أو `RUNNER_GATE_BLOCKED`.
