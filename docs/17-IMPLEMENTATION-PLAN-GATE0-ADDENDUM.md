# ملحق توجيهي على 17-IMPLEMENTATION-PLAN — قرار المالك ومراجعات GATE-0

> التاريخ: 2026-11-04.  
> **ملحق يفسر إجراءات الإغلاق، لا يعدل نص 17 ولا يغير ترتيب PH-00…PH-11 أو بوابات GATE-0…4.**

## خلاصة القرار

أقر مالك خُطوة AI أنه حصل على اعتماد الأستاذ مراد سيف للرياضيات، واعتماد المهندس محمد مراد للعقود وQA والتصميم الأمني وأن العقود جُمّدت. هذا **إقرار مالك** يتطلب مطابقة الملفات الموقعة والبصمات في أحدث مستودع قبل تغيير التقرير الرسمي إلى `APPROVED`.

## إعادة تصنيف البنود المنجزة وما يبقى

| العنصر | حالة التصميم المقصودة بعد التحقق | ما لا يُدعى اكتماله |
|---|---|---|
| DR-001 / DR-002 | منجز رياضيًا عند مطابقة وثيقة الأستاذ مراد سيف والشروط | نشر الكسور قبل PoC هاتف/حاسوب، واعتماد 151 حالة علميًا |
| DR-003 | مقبول تصميميًا عند مطابقة اعتماد المهندس محمد مراد | اختبارات CSRF/IDOR/حذف بيانات Runtime |
| DR-004 | مقبول لنسخة Schema/adapter وخطة المراجعة فقط | تشغيل Golden أو حساب دقة التشخيص |
| DR-005 | عقود مجمدة عند ربط قائمة ملفات/بصمات بإقرار المراجع | تشغيل خدمة Python أو تكامل حي مع NestJS |
| DR-009 | المراجعون مسمّون مع تواريخ/محاضر حقيقية | افتراض وجود استقلالية QA كاملة دون دليل |
| DR-010 | صاحب المنتج يجيز اعتماد البوابة وPH-01 بعد المطابقة | إعلان نجاح PH-01 قبل بنائها |

- اعتماد Prisma وفهارس/transactions قبل migrations الحقيقية ضمن PH-01/04.

- اختبارات الأمان الفعلية وعيوب الإصدار قبل GATE-3/GATE-4.

بعد أن ينتهي الوكيل من التحقق من الوثائق الأصلية ويحول تقرير `qa-reports/gate-0.md` إلى `APPROVED` مع الأدلة، يجوز له البدء بـ`PH-01` **فقط** لأن مالك المنتج أعطى هذا التفويض الصريح هنا. إذا لم تتوافر الأدلة، يتوقف عند تقرير نقص محدد ولا يتجاوز خطة المشروع.
