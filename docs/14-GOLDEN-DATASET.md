> **المراجع العليا:** `00` الرؤية، `01` المتطلبات، `02` نطاق الهاكثون، `04` الاصطلاحات العربية، `05` المنهج، `06` الأخطاء، `07` سياسة التعليم، `09` المعمارية، `10` المحرك، `11` البيانات، `12` OpenAPI، `13` AI

## 0. الغرض والسلطة وتعريف «ذهبي»

هذه الوثيقة مرجع الاختبار الذي يقارن به المطورون والوكلاء أداء **NestJS** وخدمة **Python/SymPy** ومكون التعليم الذكي. ليست بنك نشر تلقائيًا لكل الأمثلة، ولا سندًا لأن AI يعرف «ما في ذهن الطالب». يجب الفصل بين **الحكم الرياضي المثبت** و**فرضية سبب الخطأ** و**قرار التدخل التعليمي**.

- **`draft`**: مقترح خاضع للفحص، وهو وضع جميع حالات هذا الإصدار إلى أن يعتمد المختصون نتائجها.  
- **`math_checked`**: تم التحقق الحسابي من مجموعة حلول حالتي المعادلة في حالات الانتقال، باستعمال SymPy على *تمثيلات fixtures داخلية مكتوبة يدويًا*، **لا** على محلل خُطوة العربي.  
- **`subject_reviewed`**: اعتماد بشري صريح للأمثلة واللغة والنتيجة الرياضية. **لم يحدث حتى الآن**.  
- **`pedagogy_reviewed`**: اعتماد السؤال/التلميح والتشخيص والعلاج تربويًا. **لم يحدث حتى الآن**.  
- **`locked`**: تجميد إصدار مع بصمة تحقق وتاريخ ومالكي اعتماد وتغيير مضبوط؛ لا يحدث تلقائيًا بوجود هذا الملف.

**المرجعية:** `04-ARABIC-NOTATION.md` يحدد المدخل، و`10-MATH-ENGINE.md` يحدد صحة الانتقال، و`06-MISCONCEPTIONS.md` يملك الأنماط، و`07-TUTORING-POLICY.md` يملك السلوك التعليمي، و`12-API-CONTRACT.yaml` يملك أسماء JSON/API. إذا تعارضت حالة مع المرجع الأعلى تُوسم `blocked` وتُحال للمراجعة، لا يُعدّل الكود ليتوافق مع fixture غير صحيحة.

## 1. النطاق والأسس غير القابلة للتفاوض

- **P0:** معادلات جبرية خطية بمتغير واحد **س**، أعداد صحيحة، ضرب ضمني مصرح به، أقواس، كسور عددية بسيطة عند اجتياز بوابة عرضها، وتحقق على أساس **مجموعة الحلول** ضمن الأعداد الحقيقية.  
- **لا ضمن P0:** الدوال `جا/جتا/ظا`، الأسس في المتغير، الجذور، الكسور ذات المقام المتغير، الأعداد العشرية، الصور، الفيزياء، الكيمياء والبرمجة؛ توجد فقط اختبارات امتثال للحدود.  
- **حالات المحرك الست فقط:** `verified_valid`, `verified_invalid`, `syntax_error`, `unsupported`, `inconclusive`, `service_error` وفق `12` و`10`. القيمة `accepted` في قسم التحليل أدناه **وصف محلي لا اختبار لحالة MathStatus في API**؛ معناه قبول التحليل البنيوي.  
- **حالات التشخيص الخارجية:** `tentative`, `needs_probe`, `supported_by_probe`, `rejected`, `unresolved`. الرمز `none` في هذا الملف يعني **لا يوجد كائن تشخيص**، وليس حالة في OpenAPI.  
- **التلميحات:** `H0`…`H4` وفق `07`؛ لا يقدم النموذج اللغوي حكمًا حسابيًا أو يرفع مستوى التلميح من تلقاء نفسه.  
- **الكسور:** تعرض هنا باعتبارها قيمًا دقيقة؛ تفعيلها في واجهة الطالب رهن اختبار RTL في `04` وقرار GATE-1.  
- **البيانات:** اصطناعية بالكامل، لا بيانات طلاب حقيقيين، ولا تقارير نجاح مختلقة.

## 2. بنية الحالة المرجعية والبيانات المحمولة

كل حالة تحمل معرفًا ثابتًا مستقلًا لا يعاد استخدامه (`GOLD-*`). حقول السجل المنطقي الموصى بها (تسمية **Fixtures داخلية وليست DTO رسميًا للـAPI**):
| الحقل | المعنى |
| --- | --- |
| `id` | معرف ثابت مثل `GOLD-MATH-029` |
| `layer` | parse/math/diagnosis/tutoring/state |
| `scope` | `P0` أو `guard` أو `P1` |
| `raw_input / before / after` | الإدخال العربي الأصلي مرتبًا دون قلب اتجاهه |
| `expected_math_status` | قيمة `MathStatus` حين تنطبق |
| `expected_reason_code` | سبب معياري عند وجوده |
| `expected_solution_set` | تمثيل دقيق نسبي لمجموعة الحل؛ ليس مجرد تعويم عددي |
| `expected_evidence` | دليل تكافؤ أو شاهد تناقض قابل للتحقق |
| `candidate_err_code` | قائمة فرضيات مرشحة لا تشخيصًا قطعيًا |
| `expected_diagnosis_state` | أحد حالات الـAPI عند وجود تشخيص |
| `assistance_level / mode` | التلميح والسياق؛ يراعى وضع القياس |
| `problem_revision / attempt_revision` | إصدارات مثبتة في اختبار التكامل |
| `review_status` | `draft` / `math_checked` / `subject_reviewed` / `pedagogy_reviewed` / `locked` |
| `reference_docs` | مرجع القرار الأصلي وما يغيره |

**مثال بيانات حالة انتقال، لا يمثل جسم استجابة API:**
```json
{
  "id": "GOLD-MATH-029",
  "layer": "math",
  "before": "٢(س + ٣) = ١٠",
  "after": "٢س + ٣ = ١٠",
  "expected_math_status": "verified_invalid",
  "expected_before_solution": "2/1",
  "expected_after_solution": "7/2",
  "witness": "2/1",
  "candidate_err_code": "ERR-ALG-01",
  "diagnosis_is_confirmed": false,
  "review_status": "math_checked"
}
```

**ملاحظة:** هذا المثال يملك أرقامًا دقيقة بصيغة نصية متفقًا عليها في Fixtures. عقود `12-API-CONTRACT.yaml` مملوكة لذلك الملف ولا تُعدل بسبب هذه الوثيقة.

### 6.1 معايير تحويل الفرضية إلى دليل أقوى
1. وجود خطأ رياضي مثبت ودليل صالح.  
2. سؤال تأكيدي مراجع **مختلف عن مسألة النقل** وبإجابة/تفسير يسمح بتفريق سهو الكتابة عن خلل مفاهيمي محتمل.  
3. حفظ إجابة الطالب وإصدار السؤال ومساعدة سبق أن رآها.  
4. إذا دعمت الإجابة النمط يمكن استخدام `supported_by_probe` **ضمن المحاولة فقط**؛ إذا خالفته يمكن استخدام `rejected`، وإذا بقي اللبس يستخدم `unresolved`.  
5. لا تُنشأ درجة ثقة رقمية مصطنعة أو حكم «ضعف دائم» من خطوة/سؤال واحد.  

**قاعدة الاستقلال:** لا يعيد النظام سؤال التأكيد أو مثال الشرح نفسه في مسألة النقل للجلسة ذاتها. إذا تعذر توفير سؤال بديل معتمد، لا يُعلن «تحقق النقل».

### 7.1 مثال رحلة كاملة قابلة للفحص
**المسألة P-ALG-DIST-A:** `٢(س + ٣) = ١٠`، المهارة `SK-ALG-04`.

1. يكتب المتعلم `٢س + ٣ = ١٠`؛ متوقع `verified_invalid` مع شاهد `س=٢`، ومرشح `ERR-ALG-01` بحالة تحتاج تأكيدًا.  
2. يسأل النظام سؤالًا مختلفًا: «ما ناتج فك `٣(س + ١)`؟»؛ الإجابة الصحيحة `٣س + ٣`، لكن جوابًا واحدًا لا يعني إتقانًا نهائيًا.  
3. إذا طلب تلميحًا: `H1` «كم حدًا داخل القوس؟»، ثم `H2` «يضرب المعامل كل حد»، ثم `H3` كشف جزئي، وفق سياسة `07`.  
4. التدريب العلاجي المستقل: `٤(س + ١) = ٢٠`، حله `س = ٤`.  
5. مسألة نقل مختلفة في البنية السطحية: `٣(س − ٢) = ٩`، حلها `س = ٥`. لا تُستخدم مسبقًا في شرح الطالب نفسه.  
6. محاولة النقل المستقلة دون تلميحات تدعم دليلًا **محدودًا** على انتقال الفهم؛ لا تُحوّل إلى شهادة إتقان دائم.  

**عند كشف H4:** يظهر حل أصلي مثبت رياضيًا ويُوسم المسار بأنه مع مساعدة كاملة؛ على المستخدم إجراء مسألة نقل مستقلة جديدة إذا أراد دليلًا إضافيًا.

## 11. طريقة تشغيل الحالات عبر المكونات

### 11.1 محرك Python / SymPy (وحدة)
- اختبر Parser على `GOLD-PARSE-*` بالمدخل العربي الحقيقي والمواضع الصحيحة للمشكلة.  
- اختبر لكل `GOLD-MATH-*` أن الحُكم يطابق `math_status` ومجموعة الحل والدليل، وأن شاهد الخطأ يميز فعلًا.  
- اختبر أن AST يمنع الكسور بمقام متغير والضرب غير الخطي **قبل** التبسيط؛ لا تستخدم `eval` أو `parse_expr` على نص الطالب.  
### 11.2 NestJS (عقود وتكامل)
- حوّل fixtures الداخلية إلى DTO من `12` عبر Mapper واضح؛ لا تفرض أسماء هذه الوثيقة على OpenAPI.  
- اختبر `expectedRevision` و`Idempotency-Key` وإصدار المسألة وسلامة تكرار الاستدعاء، مع `GOLD-STATE-*`.  
- يجب أن يؤكد NestJS أن النتيجة ترتبط بالإصدار الحالي للمحاولة قبل تخزين تشخيص أو تحديث تعلم.  
### 11.3 AI/Tutoring
- بعد `verified_invalid` فقط، طبق قواعد الترشيح `ERR-ALG-*`، ولا تجزم بالسبب عند وجود عدة احتمالات.  
- اختبر المستوى `H0–H4` ووضع النشاط، وأن مولّد اللغة لا يغيّر المعادلات أو أدلتها أو يسرّب الحل في التلميح المبكر.  
- فشل AI يجب أن يذهب إلى قالب عربي مُراجع ولا يغير نتيجة الرياضيات.  
### 11.4 واجهة React
- اختبر أرقام `٠–٩` والمتغير `س` وRTL والنسخ/اللصق وإعادة التحرير والرسائل الصريحة عند الامتناع، مع `04` و`08`.
