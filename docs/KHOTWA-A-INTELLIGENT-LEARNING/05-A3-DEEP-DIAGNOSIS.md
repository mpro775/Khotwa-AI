# A3 — Deep Diagnosis | التشخيص العميق متعدد الفرضيات

**الهدف:** الانتقال من «خطوة خاطئة» إلى «عدة تفسيرات محتملة → سؤال تحقق قصير مراجع → دعم مناسب»، دون إعلان سبب يقيني من نتيجة واحدة. يوسّع `diagnosis.ts`, `diagnosis-rules.ts`, `diagnostic_probes` و`probe_responses` القائمة.

## سيناريو مرجعي

طالب يكتب `٣(س + ٢) = ٣س + ٢`: يمكن رصد أن التحويل غير مكافئ، لكن ذلك لا يثبت بمفرده إن كان السبب هو عدم توزيع ٣ على الحد الثاني، أو سهوًا كتابيًا، أو سوء فهم للأقواس. يعرض النظام سؤالًا مراجعًا قصيرًا **يختبر الفصل بين التفسيرات**؛ ثم يعامل الإجابة كتحديث دليل لفرضية لا حكم دائم على الطالب.

## شكل البيانات التربوية

- `observedError`: معرّف المحاولة والـstepVersion والـverificationResult والمادة والإصدار.
- `candidateCauses[]`: `errorCode`, `candidateSkillCodes[]`, `basisEvidenceIds[]`, `confidenceLabel: possible | supported | unresolved`؛ لا يقدّم نسبًا إحصائية غير معايرة.
- `probe`: معرف قالب منشور ومراجع، نوع السؤال، شرط الإجابة، `revealPolicy`, allowedAttempts, locale, predictedPatterns، ومحدد الفجوة.
- `probeResult`: `supports_candidate | weakens_candidate | unresolved | technical_abstain`؛ إذا أجاب الطالب بمساعدة تسجل المساعدة.
- `nextIntervention`: `clarifying_question | short_explanation | targeted_practice | no_safe_probe`، مع policyVersion.

## مهام التنفيذ

1. جرد فهرس `misconception_catalog` وقوالب `diagnostic_templates`؛ ربط أسباب الخطأ الموثقة فقط بالمهارات، ولا توسع mapping المعلق في `ERR-ALG-05` قبل قرار المراجع.
2. استخراج قائمة فرضيات متعددة **مقيدة بالقواعد المراجعة** وتحديد أول انتقال غير متكافئ حيث يسمح المحرك.
3. إثراء مسار probe القائم بحفظ snapshot للقالب والدليل ونتيجة التحقق وربطها بمخرجات A1/A2، دون إعادة بناء خدمة تشخيص بديلة.
4. تطبيق حالة دورة: `candidate → probe_offered → probe_answered → evidence_updated | unresolved` مع ضمان idempotency والملكية.
5. توسيع الفيزياء: خطأ القيمة مقابل الوحدة `wrong_value / wrong_unit` **لا يكفي** وحده لتشخيص سوء فهم قانون؛ أضف probe مراجع عند توفره. البرمجة: حالات قراءة code tracing فقط ضمن المحتوى المراجع؛ لا تشغيل افتراضي.
6. تقديم صياغة عربية متحفظة: «قد يكون السبب… هل تستطيع تجربة السؤال التالي؟» مع خيار «لا أعرف» وعدم إجبار الطالب على افتراض غير مؤكد.
7. ربط A1 بقرار diagnostic_probe قبل العلاج عند وجود التباس مهني، وربط A4 لاحقًا بالمتطلبات المرتبطة.

## قيود صارمة

- قرار SymPy/physics هو المصدر للحكم على الإجابة، وLLM لا يختلق `verified_invalid`, ولا يولّد probe مُنشرًا تلقائيًا.
- `unsupported`, `inconclusive`, `service_error`, `syntax_error` تنتج امتناعًا/توضيحًا تقنيًا، لا مشكلة مفاهيمية.
- لا تُكشف الإجابة أو rules_json الخاص بقالب probe في GET العام، ولا تمنح المحاولة المساعدة دليل استقلال.
- مراجعة الأستاذ مراد لـ`GOLD-DIAG-015` و`ERR-ALG-05` مسألة خارج صلاحية الوكيل. تُعلّم القضايا `review_blocked` في المحتوى المتأثر مع استمرار باقي التشخيص.

## اختبارات قبول

- [ ] خطأ واحد ينتج مرشحات محتملة فقط؛ لا `confirmed_misconception` بلا دليل مستقل.
- [ ] Probe معتمد يغير الحالة بناءً على response؛ إجابة تناقض الفرضية تُضعفها أو تبقيها unresolved.
- [ ] حساب آخر لا يستطيع رؤية probe/النتيجة، وحتى إعادة الإرسال لا تسجل إجابتين.
- [ ] نتائج المحرك غير القابلة للحسم لا تنتج probe «إصلاح ضعف».
- [ ] إجابة بعد كشف تلميح لا تدخل قياسًا مستقلًا.
- [ ] المراجع غير المعتمد أو mapping المعلق ينتج `no_safe_probe` مع استمرار مسار شرح آمن.
- [ ] يوجد مثال جبر، مثال فيزياء، ومثال امتناء تقني في Golden A3.

**مخرج A3:** تقرير مقارنة `خطأ → فرضيات → probe → تحديث أدلة` بتتبّع IDs، وعدد حالات resolved/unresolved وعوائق المراجعة.
