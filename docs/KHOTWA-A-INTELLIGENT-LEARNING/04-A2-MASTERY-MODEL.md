# A2 — Mastery Model | نموذج الإتقان متعدد الأبعاد

**الهدف:** فصل أن الطالب «تدرّب بمساعدة» عن «حل مستقلًا» و«استطاع نقل الفكرة» و«احتفظ بها بعد فترة». **مصدر الحقيقة يظل المحاولات وتقارير التحقق**، لا نسب نجاح مبنية على مشاهدة الدرس.

## النموذج المفاهيمي

لكل `(owner, skillCode, contentRelease/track context, modelVersion)` صورة **مشتقة قابلة لإعادة الحساب**:

| البعد | الحالة المقترحة | مصدر صحيح | ممنوع |
|---|---|---|---|
| exposure | `not_seen / seen` | lesson events/exposure | احتساب المشاهدة إتقانًا |
| supported_practice | `none / observed` | محاولة صحيحة مع hint/scaffold متعقب | عدها استقلالًا |
| independent_performance | `none / limited_evidence / consistent_evidence / needs_review` | مسائل مختلفة متحققة دون مساعدة | الاعتماد على إجابة LLM |
| transfer | `not_tested / evidence / needs_review` | مسألة جديدة من نوع transfer صادق | إعادة استعمال مثال معلن |
| retention | `not_due / due / observed_retained / review_needed / insufficient_data` | استرجاع مستقل بعد فاصل معلوم | عد النجاح الفوري احتفاظًا |
| evidence_quality | `insufficient / partial / eligible` مع `reasonCodes` | عدد الأسئلة وصلاحيتها وجِدتها وتنوعها | نسب ثقة 95% بلا معايرة |

لا تجمع الأبعاد إلى رقم `masteryPercent` وكأنه دقة علمية. إذا لزم مؤشّر واجهة فليكن **وصفًا عربيًا محافظًا** مع الأدلة وعددها، وليس تنبؤًا باحتمال إتقان. يحتفظ `independent_evidence` القديم باسمه وعقده؛ الحالة الجديدة **امتداد وليس إعادة تسمية مضللة**.

## قواعد الاشتقاق

1. المصدر الأصلي: `verification_reports` الحالية + `current_skill_evidence` + `subject_attempts`/physics ضمن النطاق؛ لا تُنشأ سجلات نجاح موازية. استخدم adapters تحترم تمييز correct/assisted/technical.
2. عند كل إعادة حساب اختر التقرير الموافق **لآخر revision صالح**، مع dedup حسب هوية المسألة/العائلة/المعادلة حيث يلزم؛ التعرض يقيّد الأهلية زمن التحقق كما في V2.2.
3. لكل بعد Evidence IDs وsource وpolicyVersion وasOf؛ إن لم يوجد transfer لا تعرض «أتقن النقل»؛ مراجعة مؤجلة لا تعني نسيانًا تلقائيًا.
4. نجاح أصعب أو أكثر حداثة لا يمحو أثر محاولات سابقة؛ يستعمل التاريخ لترجيح النشاط التالي والتوضيح للطالب.
5. نجاح حل مع H1 أو مساعدات A6/A7 يجب أن يمر عبر حقل support موحّد، حتى لو لم يضغط زر hint الكلاسيكي.
6. احتفظ بتغييرات النموذج عبر نسخة policy، ولا تعِد تصنيف الشواهد الماضية من غير إعادة اشتقاق موثقة.

## تكامل المنتج

- إضافة عرض «كيف عرفنا؟» داخل `StudentProgress.tsx` أو `LearningPaths.tsx`: مستقل/بمساعدة/نقل/مراجعة مستحقة، مع عدد أدلة محدود ولغة غير تشخيصية.
- ينفذ A1 قواعده بناءً على الأبعاد، لا على اسم حالة واحدة.
- API مقترح `GET /api/v1/learning/mastery?trackRevisionId=...` يعيد أبعاد المهارات و`evidenceIds` آمنة و`modelVersion` و`computedAt`; مع pagination عند التوسع، ولا يعيد بيانات طالب آخر.

## اختبارات قبول

- [ ] مشاهدة درس وحدها: exposure فقط، بلا نجاح.
- [ ] إجابة صحيحة بعد H1 أو worked partial: supported_practice فقط.
- [ ] نجاحان جديدان مستقلان مقارنان: `consistent_evidence` **بشروط V2.2** وليس ضمانًا للاحتفاظ.
- [ ] Transfer بمشكلة مألوفة مكررة يُرفض كدليل جديد.
- [ ] مهارة لم تدخل مراجعة زمنية بعد تظل `not_due`، لا retained.
- [ ] تغير خطوة أو مساعدتها أو التقرير يبطل الإسقاط القديم ويحدّثه؛ لا تغيير رجعي غير مبرر في تاريخ النتائج الموثقة.
- [ ] الإجابة `unsupported` أو فشل خدمة لا يرفع ولا يخفض البعد.
- [ ] حالات نقص بنك/غياب physics mapping/Python runner تظهر `insufficient_data` بصدق.

**مخرج A2:** تقرير حالات قبل/بعد يثبت اختلاف الأبعاد لنفس الطالب وحفظ المرجع، دون تعميم معايير علمية غير مقاسة.
