# 12 — سياسة المحتوى والمراجعة العلمية A1–A8

## لماذا هذا الملف شرط للنجاح؟

يمكن بناء محرك قرار مثالي تقنيًا لكن بلا **أنشطة منشورة ومراجعة** لن يستطيع تعليم طالب. تظهر مشكلة V2.2 في `qa-reports/V2.2-CONTENT-INVENTORY.md`: 18 درسًا في ثلاث مسارات، لكن 10 منها هياكل عامة، وحِزم الأسئلة الـ76 مسودات لا تكفي وحدها لإطلاق تجربة تعليمية كاملة. المقصود هنا **إعداد قوالب وعينات للمختبر**، لا اختلاق موافقات أو نشر آلي لطلاب حقيقيين.

## حزم محتوى مطلوبة لكل مهارة محل التجربة

| نوع المحتوى | A المرتبط | ما يجب مراجعته |
|---|---|---|
| Objective + worked explanation | A1/A6 | الهدف، مستوى الطالب، الدقة العلمية، العربية والمصطلح |
| Distinct diagnostic probes | A3 | أن كل اختيار يفصل بين تفسيرات لا يثبتها الحكم وحده، ولا يكشف إجابة القياس |
| Prerequisite edge rationale | A4 | لماذا هي مطلوبة أو مفيدة، وما نطاقها المنهجي، ومن راجعها |
| Retrieval questions | A2/A5 | الجِدة والأسر/التكافؤ وصعوبة السؤال ووقت قياس الاحتفاظ |
| Scaffold completion steps | A6 | خطوات الحل الصحيحة، العِبَر المستهدفة، البدائل الصحيحة، وما تكشفه المساعدة |
| Socratic turns/templates | A7 | سؤال واحد/تلميحات محدودة، منع إعطاء الحل، امتناع التقنية |
| Planning/reflection prompts | A8 | صياغة غير حكمية، إتاحة، خصوصية، ملاءمة العمر |

## متطلبات استوديو المحتوى

1. في `ContentStudio`/`PathStudio`: حقل `activityType`, `skillCodes`, `prerequisiteSkillCodes`, `contentRevisionId`, `reviewStatus`, `safetyFlags`, `evaluationMethod`, `evidenceEligibility`، دون HTML خام أو prompt يدخله الطالب للتنفيذ.
2. فصل **معاينة الاستوديو** عن **النشر**. validation لسلامة JSON/الصيغة/المراجع لا يعني اعتمادًا تربويًا.
3. مراجعة math examples عبر SymPy وفق النطاق، physics examples بالقيمة والوحدة، Python code examples بوسائل آمنة دون تنفيذ كود غير موثوق.
4. فصل بنوك `worked_example`, `guided_practice`, `diagnostic_probe`, `independent_check`, `retrieval_review`. عند مشاركة عائلة/معادلة يمنع استعمالها في قياس مستقل للطالب الذي شاهدها.
5. سجل توقيع المراجع على **revision/hash**، وعند التعديل تنشأ نسخة جديدة مع إعادة مراجعة ما تأثر؛ لا ترث موافقة عامة من مادة أو درس آخر.
6. الترجمة/العربية: أرقام `٠١٢٣٤٥٦٧٨٩` والمتغير `س` حيث ينطبق، وPython LTR والمحارف المحجوزة بالإنجليزية، والوحدات العلمية الدولية واضحة.
7. توافر `safe fallback` من نص نشر/قالب معتمد لكل نوع نشاط قبل تفعيل عرضه لطالب غير اصطناعي.

## أول مجموعة محتوى عمودية للتطوير

- **الجبر — توزيع الأقواس (`ALG-L04`, `SK-ALG-04`):** دورة كاملة A1→A8: مثال صحيح، probe تحقق للأخطاء، متطلب، تمرين جزئي، سؤال مستقل جديد، مراجعة مؤجلة، جلسة سقراطية، تأمل.
- **الفيزياء — الحركة بسرعة ثابتة (`PHY-L01`):** محرك قيمة ووحدة، سؤال كشف منفصل عن خطأ الوحدة، مراجعة مستقلة جديدة؛ لا يتوسع إلى محاكاة حرة أو B2.
- **Python — الطباعة/المتغيرات (`PY-L01`):** واجهة شرح وقراءة وreflect فقط مع ضبط prompt المتكرر `Hello`; لا يحسب نجاح حل برمجي ولا ينفذ Runner دون موافقة فنية.

**حالة الاعتماد:** أمثلة هذه المجموعة في هذا المستند أهداف اختبار فقط وليست محتوى معتمدًا. عندما يغيب توقيع مختص المادة تبقى مواد الاختبار موسومة `synthetic_only` أو `draft` مع عدم عرضها للمتعلمين الحقيقيين. قرارات معلقّة `GOLD-DIAG-015` و`ERR-ALG-05` لا تحسم ضمن الحزمة.

## حد أدنى للمراجعين

| الدور | يراجع |
|---|---|
| معلم رياضيات (المراجع المحدد بالمشروع) | صحة الأمثلة، أخطاء الجبر، probes، التعريفات والعلاقات، التلميحات |
| مختص الفيزياء | الوحدات والكميات والقوانين ونطاق الصلاحية وسؤال التمييز |
| مختص برمجة | دقة قراءة Python، تمارين التتبع والصياغة وملاءمة الأساسيات |
| QA/أمن/معمارية | سلامة الحقول والمساعدات والقياس وعدم التسريب وموافقة العرض الحقيقي |
| مالك المنتج | نطاق التجربة وتفعيل ميزات وإطلاق تدريجي وحدود AI الخارجي |

التوقيع البشري قرار مستقل؛ **لا تكتب أن المراد سيف أو غيره وافق على محتوى جديد اعتمادًا على موافقات قديمة**.
