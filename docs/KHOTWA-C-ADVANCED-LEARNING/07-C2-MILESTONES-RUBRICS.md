# C2 — دورة حياة المشروع والمعايير وقرار الإتقان

## الحالة (server authoritative)
```text
available -> active -> draft_submission -> awaiting_feedback
  -> revision_requested -> active -> submitted_final -> review_pending
  -> feedback_ready -> completed
                 ↘ paused / withdrawn (محكوم)
```
يمكن تقديم milestone على حدة، مع versioned artifacts. لا ترجع مشروعًا `completed` إلى `active` بتعديل صامت؛ أنشئ submission revision جديدة وفق policy.

## Rubric مبدئي قابل للتخصيص مع حارس تربوي
| المعيار | 0: يحتاج دعمًا | 1: جزئي | 2: متحقق |
|---|---|---|---|
| فهم المشكلة ومتطلباتها | هدف غير واضح | بعض المتطلبات | هدف/حدود موثقة |
| نموذج/مبدأ علمي | غير قابل للتحقق | بعض الصحة | صحيح ضمن نطاق معتمد |
| جودة الحل/المنتج | غير مكتمل | يعمل جزئيًا | يقدم سلوكًا/تمثيلًا سليمًا |
| التبرير والتوثيق | غير موجود | وصف بلا تبرير كاف | تبرير/اختبارات مناسبة |
| المراجعة والتعلم | لا مراجعة | تعديل بلا سبب | تحسين موثق مع تفسير |

**مهم:** الدرجة المركبة اختيارية ولا تُحسب آليًا عندما يحتوي rubric على عناصر مفتوحة غير قابلة للحكم الموثوق. الحكم البشري ذو provenance؛ LLM إن استُخدم يعرض **مسودة ملاحظة** فقط مع إسناد أدلة، لا ينشر النتيجة بمفرده.

## التسليم والاستقلالية
- سجّل `assistanceSummary`, `templateUse`, `AIHelpSeen`, `reviewFeedbackSeen`, `exposureFamily` بلا ادعاء دقة معرفية مفرطة.
- مشروع ناجح مع استخدام دعم يمكن احتسابه تطبيقًا **بمساعدة**، مع اقتراح سؤال/تحد جديد مستقل لقياس الإتقان.
- إذا أنجز الطالب artifact ثم أصلحه بعد رؤية الحل/التعليقات، فإن قبول المشروع لا يطهر أثر التعرض على سؤال التقييم السابق.
- ضع `humanReviewRequired` للمشاريع المفتوحة التي تحتاج تأكيدًا تربويًا؛ لا تعليق كامل المنصة إذا غاب المراجع، بل حالة pending واضحة.

## قابلية المقارنة عبر نسخ Rubric
- `rubricRevisionId`, `assessedSubmissionRevisionId`, `criterionId`, `level`, `reviewerId/type`, `reviewedAt`, `reason`.
- لا ترث submission القديمة rubric جديدًا بصمت؛ اعرض سياسة تحول/إعادة مراجعة صريحة.
- لا تعرض معايير خاصة سرية (hidden grading keys) في واجهة الطالب قبل السماح بها.

## حواف مهمة
مشروع مسحوب، إعادة رفع نفس الملف، تعديل أثناء مراجعة، مراجعتان متزامنتان، طالب يغلق المتصفح ويعود، Reviewer يغير دوره، نشر نسخة مشروع جديدة بينما مشاريع قديمة نشطة، ملفات غير مقبولة، وتعذر خدمة AI.
