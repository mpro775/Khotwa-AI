# تقرير DEV-07 — Python للمبتدئين

- Task/branch: DEV-071…078، `codex/posthack-roadmap`؛ الحالة: المصدر جاهز للمراجعة، تشغيل sandbox الفعلي مؤجل بطلب المستخدم.
- المراجع: AGENTS، 00/01/02، 07/09/11/12/13/15/16، وخطة V2.1 ووثيقة الامتداد19؛ FR-033…042 وFR-048…054 للسياسة والملكية، دون توسيع محلل الجبر.

## المنفذ

ستة دروس و20 تمرينًا مؤلفًا بصيغة **draft**: الطباعة والمتغيرات والحساب والشروط والتكرار والدوال. لكل تمرين وصف عربي، بداية كود، حل مرجعي خاص، اختبارات علنية ومخفية، وتلميحات H1…H4 غير مراجعة بعد. لا حلول أو hidden tests ضمن كتالوج الطالب أو bundle المتصفح. يمكن للمشرف استيرادها وتحريرها واختبار الحل المرجعي في sandbox ثم اعتمادها ونشرها من الاستوديو نفسه.

محرر LTR بواجهة عربية يحفظ النص الخام، وTab/Shift+Tab والمسافات والأسطر، وEscape للخروج بلوحة المفاتيح. زران للتشغيل التجريبي وتسليم جميع الاختبارات؛ تشغيل الحالات العلنية لا يمنح دليلًا مستقلًا. استعادة المحاولة من الحساب تحفظ الكود والمساعدة والإصدار حتى بعد أرشفة السؤال. التلميحات المراجعة تدريجية؛ H4 يتطلب تأكيدًا ولا تمنح المساعدة نجاحًا مستقلاً. لا يرسل هذا المسار كود طالب إلى Gemini؛ لا يتغير الحكم اللغوي بسبب تلميح.

NestJS يحفظ المحاولة قبل الإرسال إلى `Judge0Runner`. حد الموارد في كل طلب: CPU/ذاكرة/عمليات/مخرجات، و`enable_network:false`؛ حدود يومية وبالدقيقة لكل مالك. المحول يشترط تهيئة صريحة لنسخة Python ومفتاح الخدمة وإفادة مشغل بالعزل؛ لا ينفذ Python أو shell أو Docker داخل API أو SymPy. المهلة الإجمالية للتقييم محدودة وتلغي الطلبات؛ النتيجة المتأخرة لا تعدل مراجعة جديدة. مفتاح الإرسال لا يعيد تشغيل job مضاعف، والطلبات العالقة تستعاد كتعذر مع بقاء الكود.

النتيجة مبنية على المخرجات/حالات استدعاء الدوال، وتقبل كودًا بديلًا. مخرجات وأخطاء الاختبار المخفي لا تعاد للطالب. تمرير أي حالة لا يكفي وحده، ولا يتحول SyntaxError/Timeout/تعطل Runner إلى نجاح. تُحفظ أحداث التنفيذ والمساعدة. واجهات `/programming/problems` و`/programming/attempts` وتفاصيل المحاولات والتلميحات كلها خلف NestJS مع تفويض المالك وCSRF/مراجعات المحاولة.

## الملفات والتشغيل المؤجل

`apps/api/src/programming.ts` و`programming-runner.ts` و`product-core.ts`، `apps/web/src/SubjectWorkspace.tsx` و`code-editor-model.ts`، `apps/api/data/python-basics.draft.v1.json`، migrations0012/0014/0015، OpenAPI12 ومكونات استوديو المحتوى. إعداد المحول في `ops/runner/README.md` و`runner.env.example`. إعداد sandbox حقيقي مسؤولية تشغيل منفصلة؛ لا Compose يدعي أن حاوية عادية تحقق العزل.

1. بعد تجهيز DB اختبار وحساب المشرف، استورد المسودات وراجعها.
2. جهز Runner خاصًا ومعزولًا وفق دليل المشغل، وأثبت حدوده، ثم فعّل المتغيرات على الخادم فقط.
3. اختبر مرجع تمرين الطباعة ثم دالة الجمع من الاستوديو قبل النشر.
4. من حساب الطالب جرّب حلًا صحيحًا بديلًا، ثم RuntimeError وحلقة غير منتهية، وتلميحًا وإعادة تسليم واستئنافًا من جلسة جديدة.
5. في بيئة sandbox الاختبار فقط، افحص الملفات والشبكة والموارد وسرية الاختبارات، وافصل الخدمة للتأكد من بقاء الكود.

الفحوص الخفيفة الفعلية في التقرير الموحد وJSON الأدلة: العقد والإسقاط الخاص/العام، محول مزيف لا يتصل بالشبكة، حدود المخرجات والمهلة الكلية، مقارنة الحالات دون تطابق نص الحل، وتحريم التفعيل دون إفادة عزل. **لم ينفذ أي كود طالب أو مرجع في sandbox فعلي، ولم ينشر تمرين جديد.** لا نجاح مزعوم لفحص الملفات/الشبكة/الموارد على خادم حي. تشغيل Runner وE2E والعزل الفعلي والمراجعة التعليمية NOT_RUN_BY_REQUEST؛ لذا قبول V2.1 التشغيلي بانتظار المرحلة المنفصلة.
