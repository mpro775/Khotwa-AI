# تقرير تنفيذ C3 وواجهات C1–C5

- Task IDs: C3-01/C3-02، واجهات C1-03/C2-03/C4-01/C4-02/C5-02.
- الفرع: `codex/intelligent-learning-a`؛ لم يُنشأ commit أو push.
- الحالة: `PASS_TESTED` لفحوص المصدر المذكورة؛ `PARTIAL / BLOCKED_LAUNCH` للقبول التشغيلي والإنساني.
- الوثائق المالكة: AGENTS، الرؤية والنطاق، حزمة C خاصة 03–17 و19 و22–25 و29 و31؛ تكامل مع عقود A/B القائمة.

## ما تغيّر ولماذا

- `apps/web/src/advanced-learning/`: مساحة مشكلة مع مراحل الفهم والخطة والتجربة والتفسير والتأمل؛ الحفظ التلقائي للمراحل، الحفظ اليدوي والاستئناف، إخفاء التغذية الراجعة عند تغير المسودة، CAS وعدم تكرار العمليات عبر ProductApi. يرتبط التحقق بأداة المادة القائمة أو البنك؛ لا حكم محلي أو إتقان من الإكمال.
- مساحة مشروع تعرض السؤال والمعايير والمعالم، الحفظ التلقائي للملاحظات، منتجات نص/JSON محدودة، نسخ التسليم والتغذية الراجعة ومصدرها، التحسين والتسليم النهائي والحالة والانسحاب. يمنع إغلاق مساحة المنتج مع مسودة غير محفوظة. التقييم المستقل يمر بخدمة A2 الأصلية.
- خيارات عرض محلية: حجم النص والتباين وتقليل الحركة، لا تشخيص أو تصنيف لأنماط التعلم. بديل نصي حاضر، جدول ذو caption ورؤوس صفوف وأعمدة، عزل LTR للكود، أسماء وحقول عربية، أزرار أصلية للمفاتيح، تركيز ظاهر، دون مؤقتات عقابية.
- `LessonRenderer` و`LearningPaths`: عرض وفتح أنشطة C والتمثيلات من إصدار درس مثبت. تبقى المعاينة في Studio دون جلسة أو دليل. `IntelligentLearningPanel` وdecoder يحفظان مراجع A1 المتقدمة ويفتحان جلسات الدعم A6/A7/A8 الأصلية ويركزان مساحة الدعم.
- `PathStudio`: مكتبة قابلة للتصفية حسب نوع نشاط C، تحذير mappingPending، تأليف منظم للمشكلة والمشروع والتمثيلات والمعايير والحقول الخاصة، أربع مجالات مراجعة مرتبطة بالبصمة، عارض مشروع للمراجع المخول ومؤشرات جودة المحتوى. لا استوديو مكرر أو موافقات بشرية مصطنعة.
- لوحة الطالب تفصل عدادات النشاط عن المؤشرات المستقلة؛ تعرض العينة والبسط والمقام والنافذة والنسخة ومصدر البيانات والنقص. المقام الفارغ والمؤشر المحجوب يعطيان قيمة null، لا صفرًا بالمئة. مؤشرات مجموعات الطلاب محجوبة وفق سياسة الخصوصية المعلقة.
- decoders allowlist عامة منفصلة عن التأليف: لا تدخل مفاتيح الحلول أو rubrics الخاصة أو الاختبارات المخفية إلى حالة الطالب أو المعاينة.

ظهر إخفاق انحدار أولي عند تحميل CSS من LessonRenderer بواسطة loader اختبارات SSR القديم؛ نُقل استيراد CSS العام إلى `main.tsx` وأعيد تشغيل 42 اختبارًا فاجتازت. ظهر lint واحد لمسافات regex في الاختبار؛ صحح باستخدام `{4}` وأعيد lint دون أخطاء. لم تُخفّض توقعات الاختبار.

كشفت المراجعة المصدرية الأخيرة أن التنقل الداخلي قد يفقد نصًا لم يُحفظ خادميًا، وأن إجابة التحقق المنفصلة لم تدخل حارس المسودة. أضيف cache محدود في `sessionStorage` لنصوص الطالب المعلقة فقط، تحت بادئة الحذف عند تغيير الهوية. لا تُستعاد إلا بعد GET يثبت ملكية الجلسة نفسها؛ تطابق revision يسمح باستعادة النص بوصفه مسودة غير متحققة، واختلافه يتطلب اختيار استعادة صريح بعد عرض تحذير ومقارنة. لا تُخزن نتيجة حكم أو موافقة أو مفتاح حل. خمسة اختبارات إضافية تثبت الإسقاط الخاص، الربط بالجلسة، الإصدار، فساد/كبر cache، تنظيف الهوية، وتعذر التخزين. أُصلح كذلك بقاء busy في مؤشرات المحتوى عند تغيير الإصدار أثناء طلب سابق. فحوص البناء النهائية بعد هذا التعديل يسجلها تقرير الجذر.

## ما لم يُشغّل وما بقي

- `NOT_RUN`: هاتف فعلي، zoom 200/400%، NVDA/VoiceOver، مسار لوحة مفاتيح في متصفح، contrast audit وaxe إن توفر. SSR يثبت بنية markup وبعض تسرب البيانات؛ لا يثبت مطابقة WCAG 2.2 AA.
- `NOT_RUN` بواسطة وكيل الواجهة: تشغيل خدمات، نشر، AI خارجي، Runner، PhET، migrations. تقرير الجذر يسجل اختبارات HTTP/DB الاصطناعية المستقلة ونتائجها.
- موافقات المادة والتربية والوصول والأمن والخصوصية والترخيص بشرية: بانتظار؛ سجلات مراجعة المصدر TEST_ONLY لا توقع عنها.
- المحتوى synthetic والأعلام مغلقة افتراضيًا؛ لا قبول إنتاجي أو فعالية تربوية مُثبتة.
- إذا منع المتصفح التخزين المحلي أو نفدت الحصة، تبقى المسودة في الذاكرة فقط حتى الحفظ الخادمي؛ الرسائل تشترط توفر التخزين ولا تدعي ضمان الاستعادة. التخزين محلي لعلامة التبويب ويُمحى عند تبديل هوية المستخدم؛ لا نسخ إلى analytics أو logs.
- بيانات cohort ورفع الملفات والربط بين مواد مختلفة محجوبة أو خارج النسخة المصرح بها. التقييمات الخام لا تدخل التحليلات.
