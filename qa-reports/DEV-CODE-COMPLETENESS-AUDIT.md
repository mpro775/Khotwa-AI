## طريقة إثبات الربط وحدود الفحص

قُرئت استدعاءات React وعميل نفس الأصل، وتسجيل controllers/factories في BusinessModule، والتحقق والتفويض والإصدارات، وعمليات التخزين والقيود في migrations، وإسقاط المخرجات والمحولات الداخلية. أمثلة المسارات المتتبعة:

- `AccountPanel → /auth/email/* → AccountService → auth_sessions/guest_account_claims → Store bridge → pinned attempt reads`؛ أُصلح اسم عمود exposure الخاطئ بدل افتراض أن endpoint يعمل.
- `ContentStudio → /studio/items/:id/validate → validatePayload → MathGateway/PhysicsGateway/RunnerPort`، ثم review/publish ودورة release جديدة وcatalog/start؛ كان استدعاء التحقق من واجهة المعلم مفقودًا وأصبح متصلًا في هذه الجولة.
- `ProgrammingWorkspace → ProgrammingController → ProgrammingService.submit → subject_attempts/events → Judge0Runner → evaluateProgram → إعادة التفويض/المراجعة → النتيجة/الاستئناف`؛ تسليم run لا ينشئ دليلًا مستقلًا لمجرد اجتياز العلني.
- `PhysicsWorkspace → PhysicsController → PhysicsService → PhysicsGateway → /internal/v1/physics/verify → متحقق Python المستقل`؛ لا دمج بوحدات الفيزياء داخل محلل الجبر، ولا DB داخل Python.

الفحص الساكن الآلي في [DEV-CODE-COMPLETENESS-STATIC.json](DEV-CODE-COMPLETENESS-STATIC.json) يقرأ AST وDDL والعقد وملفات المحتوى. راجع 300 قالب SQL، وأسماء أعمدة 70 عملية INSERT و65 عملية UPDATE مقابل 46 جدولًا، و36 عملية controller للمنتج، و64 حمولة محتوى، وبصمات المراجع. لا يفسر SELECT/PLpgSQL تفسيرًا كاملًا كما يفعل PostgreSQL، ولا ينفذ SQL، ولا يثبت صحة المعاملات أو العزل أو جميع سلوكيات الواجهة. اكتشف التدقيق اليدوي تبعيات FK لا يكشفها هذا الفحص وحده.

## Runner — كود الربط والإعداد الآمن

النقل من NestJS إلى Judge0، والتخزين قبل الإرسال، واستطلاع النتيجة والمهلة الكلية والمقارنة والمخرجات المجملة وربط المحاولة، كلها موجودة في المصدر. لا يُشغّل كود الطالب داخل NestJS أوSymPy، ولا يُفتح له Docker socket. **تكامل جميع مداخل Runner جزئي بسبب CODE-06، وعرض نتيجة المعلم جزئي بسبب CODE-05**؛ وجود المحول وحده لا يغلق هذين النقصين.

للتهيئة اللاحقة، يلزم خادم Judge0 أو موفر موثوق معزول فعليًا، ونسخة Python وlanguageId مطابقان، وشبكة خاصة مع ACL، وTLS عند عبور شبكة غير خاصة، ومفتاح خادمي. يجب أن يطبق الخادم حدود CPU والذاكرة والعمليات والمخرجات، وأن يحجب عن الكود الشبكة وملفات المضيف وامتيازاته وأسراره وDocker socket. بعد ذلك تُفحص محاولات الملفات والشبكة والحلقات والذاكرة، والحلول البديلة وسرية الاختبارات المخفية، داخل العزل نفسه. `RUNNER_ISOLATION_ATTESTED=true` إفادة مشغّل بعد الفحص، وليست إثباتًا تنتجه الشيفرة. المحول معطل، وقيمة اللغة 0 تمنع التفعيل المجهول؛ لم يُنشر أو يُشغّل Sandbox هنا.
