## التنفيذ وحدود العرض

المسار المختبر: عميل HTTP بعقد OpenAPI وجلسة ضيف وCSRF → **NestJS الفعلي** → PostgreSQL ومحرك Python/SymPy الحقيقي → تشخيص النظام → إسناد علاج → طلب تلميح عبر Gemini → AJV والتحقق الدلالي → حفظ المساعدة → إكمال العلاج وإسناد نقل جديد. استُعملت استدعاءات `/api/v1/attempts/{id}/hints` داخل الرحلة؛ لم يقتصر الإثبات على curl أو استدعاء مستقل للمزود.

- يستخدم المحول `generateContent` و`responseMimeType=application/json` و`responseJsonSchema` و`thinkingConfig.thinkingLevel`. يقرأ النموذج والتفكير والمفتاح من بيئة الخادم؛ المفتاح يرسل برأس `x-goog-api-key`، وليس ضمن URL أو ملفات الشيفرة أو التقارير.
- مصدر المخطط المحلي هو مخطط PH-07 نفسه، مُصدَّر دون تعديل دلالته. يمر الرد عبر `validateTutorReply` محليًا في المحول ثم الخدمة. تحويل `const` إلى `enum` مكافئ في مخطط المزود فقط.
- القبول الدلالي مقيد **حرفيًا بقالب النص الحالي وصيغه الموجودة** وبمستوى H1–H3 الذي يختاره NestJS. لا تُعرض صياغة حرة جديدة من النموذج؛ `isAnswerRevealed=false` لا يمنح السماح وحده. لا توليد لمسائل أو مفاتيح حلول أو حكم رياضي من Gemini.
- السياق المرسل محدود بالقالب وإصداراته والمهارة والملاحظة المتحفظة؛ لا نص طالب خام أو معرفات جلسة/محاولة أو حلول مخفية أو تاريخ محادثة أو أسئلة نقل مغلقة. معرّف القالب غير الشخصي موجود لربط التحقق.
- العزل بـAsyncLocalStorage بعد تفويض المورد وفحص الإسناد. لا استدعاء للمزود لمسألة الجذر/PH-07، ولا عند إسناد النقل أو قراءته أو التحقق منه مستقلًا؛ طلب المساعدة الصريح يثبت الخروج من القياس قبل الاتصال. PH-09 يجب أن يكون معطلًا، والتشغيل مقتصر على بيانات اصطناعية.
- H4 ومسائل العلاج والنقل تأتي من المحتوى القائم؛ SymPy يظل مرجع الرياضيات. **المحتوى والقوالب draft اصطناعية غير معتمدة تربويًا**، لذلك بقي `generationSource=manual` بدل اختلاق `llm_validated`؛ سجل التدقيق الداخلي يثبت استخدام Gemini والنموذج الفعلي والرموز عند حدوثه.
- أضيفت قياسات التدقيق عند إدراج الحدث نفسه وفق الموافقة الثانية؛ لا تعديل لاحق لتاريخ غير قابل للتغيير. قوالب fallback الحالية تخضع لحدود المحتوى نفسها.

## الحصة والمفاتيح والمهلة

- نافذة متحركة حقيقية: **10 حجوزات/60 ثانية**، محفوظة مع سقف الجولة في ledger خاص مستديم قبل الإرسال. أقصى ما رُصد فعليًا **8 طلبات في أية نافذة 60 ثانية**. لا SDK أو retry تلقائي أو اختبار حمل؛ الاتصال تسلسلي.
- سقف الجولة 10، قابل للضبط بين 10 و15 فقط. فشل HTTP أو المهلة يستهلك الحجز. الطلب الحادي عشر عاد إلى fallback **دون اتصال إضافي**. سجل الجولة المستخدمة محفوظ في `.local/ph08-gemini-first-round.json`؛ لا تعِد تهيئته لتجاوز الحصة.
- `GEMINI_DAILY_REMAINING=unlimited` استند إلى تصريح المستخدم الصريح. عند وجود حد يومي يطلب الإعداد المتبقي الفعلي، ويأخذ الأصغر منه ومن سقف الجولة. القيمة المجهولة/غير الصالحة توقف التفعيل. صلاحية هذه الجولة ساعة تشغيلية، وليست ادعاء وقت تصفير يومي لدى Google.
- القفل الحصري يمنع تشغيل نسختين على ledger نفسه؛ إعادة التشغيل لا تعيد الرصيد. بعد crash لا يحذف القفل تلقائيًا: يتحقق المشغل من توقف العملية قبل إزالة القفل فقط، مع إبقاء ledger. الضبط **محلي لنسخة/مشروع اختبار واحد**، ولا يدّعي حوكمة استدعاءات برامج أخرى تستخدم حساب Google نفسه أو تشغيلًا موزعًا.
- المهلة الافتراضية 8000ms؛ الطلب الثامن تجاوزها. توقفت الجولة الأولى عند 8 دون إعادة. استُكمل الطلبان المتبقيان على حالتي مساعدة النقل، بنفس ledger ونفس سقف 10، وبـ`PH08_GEMINI_TIMEOUT_MS=15000` تحت مهلة الطلب الكلية 20000ms. لم يُعَد إرسال الطلب المنتهي بالمهلة.
- المفتاح حُقن في بيئة عملية الاختبار والحاوية فقط، وأزيلت حاويات المهمة وملفات إعدادها المحلية المؤقتة. لا قيمة مفتاح في أدلة التسليم، ولا تغيير لبيئات PH-07/09 الموجودة.

عينة مبنية على تشخيص النظام: أصل `٢(س + ٣) = ١٠` وخطوة `٢س + ٣ = ١٠` أعادا `verified_invalid` و`ERR-ALG-01 / needs_probe`. اختير العلاج `٢(س + ١) = ٨`؛ التلميح H1 المقبول: «انظر إلى الحدين داخل القوس: هل تأثر كل منهما بالمعامل؟». H2: «المعامل خارج القوس يضرب كل حد داخله.» لا إجابة نهائية، ولا جزم بضعف الطالب. النصوص الكاملة ومراجع التشخيص الاصطناعية محفوظة في أدلة العينات، دون رموز جلسات أو أسرار.

أسماء سياقات الجدول تصف المهارة المؤلفة في البنك، ولا تعني تشخيصًا مؤكدًا في كل حالة: بعض المحاولات أعادت `diagnosisCandidate=null`، فاستعمل المسار التلميح العام «راجع ما تغير في طرفي المساواة.» دون اختراع نمط أو إصلاح التشخيص الموروث. العينتان النوعيتان واضحتا التشخيص هنا هما التوزيع والمعامل السالب؛ الأخيرة انتهى استدعاؤها الحقيقي بالمهلة واستخدمت أصل القالب.

البيئة: Windows للمراجعة الثابتة، وحاويات Linux محلية ببيانات اصطناعية مؤقتة؛ PostgreSQL 17.6، محرك SymPy `0.3.0`. أُعيد استخدام dependencies من الصورة المحلية مع **مطابقة SHA-256 لملف package-lock**، ثم تُرجم المصدر الحالي داخل الحاوية. لا إعادة بناء واجهة أو تغيير dependencies؛ لا منافذ عامة لـDB أو Python. طُبقت migrations القائمة على DB جديدة tmpfs فقط؛ migration 0009 موجودة أصلًا في HEAD، وPH-09 معطل.

فحوص التكامل شملت: HTTP 503، الإلغاء عند المهلة، رفض «س = ٩٩» رغم علم عدم الكشف الكاذب، الرد المتأخر بعد تعديل الخطوة، عدم اتصال مسائل الجذر، حفظ النص الخام والمراجعة وحكم SymPy، idempotency دون توليد إضافي، إكمال العلاج والنقل المستقل دون اتصال AI أو تسريب حل، الخروج الصريح من القياس قبل المساعدة، والحصة المنتهية. HTTP 503 وتسريب النص والسباق أعطال **محاكاة**؛ المهلة الثامنة عطل حقيقي. المخرجات المحاكاة موسومة `transport=controlled`، ولا تدخل إجمالي Google.

جولات تطوير أولية غير ناجحة صُححت قبل التسليم: ترتيب تنظيف اختبار ledger، واستدلال TypeScript، وحقول fixture، ومحاولة تدقيق لاحق تمنعها immutability. استُبدلت الأخيرة بالحقن الذري بعد موافقة المستخدم. [أول دليل فشل محلي](ph08-gemini-controlled-initial-run.json) محفوظ للشفافية؛ النتائج النهائية المحلية اجتازت. لا إصلاح لعيب موروث خارج هذا التكامل.

## المتبقي والمراجعة

لا تغيير في OpenAPI أو JSON العام أو Golden أو schema أو migrations أو محرك الرياضيات أو ملفات PH-09. لم تبدأ PH-10/11، ولم يُشغّل حمل أو نشر أو تجربة بأشخاص حقيقيين. لم تُشغّل مجموعة Golden الكاملة أو UI/هاتف أو اختبارات المراحل الأخرى غير الوحدات التابعة مباشرة لهذا التغيير؛ المهمة تكامل خلفي مستهدف، ولا أدلة قبول جديدة للأجهزة من هذا التقرير.
