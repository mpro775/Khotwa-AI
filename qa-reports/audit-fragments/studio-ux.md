### متابعة دليل DEV-031 وDEV-033 وDEV-034 بعد إصلاح الربط

`ContentStudio.transition` عند497 يرسل الآن **EXISTING** `/studio/items/:id/validate` أولًا عند action=submit، ويحفظ checked.validation في النسخة والقائمة لتظهر الملاحظات الحالية. إذا كان valid=false تبقى draft ولا يرسل transition. عند النجاح يأخذ editRevision من جواب التحقق نفسه، ثم يرسل submit. فشل الشبكة أو409 لا يستبدل payload الخام. editEpoch في426/462/467 وحراسته بعد كل await تمنع استجابة قديمة من استبدال مسودة تغيرت، وزر «مسألة جديدة» معطل أثناء العمل. لا endpoint أو DTO جديد لهذه المتابعة.

هذا يغلق وجود API تحقق غير مستعمل في الواجهة، ويمكّن teacher/content_manager من اختبار المرجع قبل مراجعة admin. يستمر قرار DEV-031/033/034 **IMPLEMENTED** على مستوى الربط المراجع، مع اعتماد النتيجة التشغيلية لاحقًا. عرض تفاصيل اختبارات Python العلنية/المخفية لا يزال نقصًا مستقلًا في DEV-077، ولا يحوّل مجرد ربط الزر نتائج valid/issues إلى تفاصيل حالات غير موجودة.

## الفجوات الحقيقية وما لا يعد فجوة مصدر

قرار DEV-037 النهائي **PARTIAL**: CRUD والأدوار والعقود موصولة، لكن successful transition retry يفحص expectedRevision قبل productMutation/replay وقد يرفض إعادة إرسال نفس العملية المكتملة بـ409؛ ويبدأ العمل المكلف قبل cache كما في DEV-073. هذا نقص في الالتزام المشترك بـIdempotency، ولا يغير اكتمال دورة الحالات والتحقق نفسها في DEV-032/034.

1. **باقية — DEV-035:** authoring تلميحات مخصصة لنمط الخطأ ERR-* غير موجود؛ لا يعالجها SMTP أو migration أو اعتماد النصوص. توجد تلميحات عامة سليمة ومراجعة، فلا يوصف كل بنك التلميحات بأنه مفقود، ولا يوصف الربط بالخطأ بأنه كامل.
2. **عولجت محدودًا — DEV-033:** غياب exact skill/difficulty filters. أضيفت حقول اختيارها في React، إرسالها وتحققها وتطبيقها في SQL، ومخطط الاستعلام في generator.
3. **عولجت محدودًا — DEV-036:** export كان يحذف هوية وإصدار كل revision. أبقي items للاستيراد القديم وأضيف revisionMetadata aligned معها؛ ليست آلية استيراد نسخ تاريخية جديدة.
4. **عولجت محدودًا — DEV-031/034:** قبول عدة skillCodes ثم إسقاط الثانوية عند materializeAlgebra. أضيفت skills وproblem_skills coverage secondary في الإصدار الجديد، مع dedup واستبعاد primary؛ التشخيص والتدخل ما زالا مستهدفين للمهارة الأساسية دون اختراع سياسة متعددة المهارات.
5. **عولجت محدودًا — حفظ المسودة:** زر إزالة المسودة ودالته يمنعان التنفيذ مع dirty حتى لا تستبدل تغييرات خام غير محفوظة برد نسخة مؤرشفة.
6. migrations/DB والنشر والمزودات واعتماد المسودات وتقييم الأجهزة/قارئ الشاشة/200% ليست نواقص برمجية تلقائيًا. لكنها لا تزال مانعة لادعاء قبول تشغيلي.
7. **عولجت محدودًا — DEV-033/034:** زر «تحقق وأرسل» كان يستدعي submit فقط، ومسار validate لم يستعمله React. أضيفت سلسلة التحقق ثم الإرسال وحراسة النص/النسخة المذكورة أعلاه.
8. **باقية مشتركة مع تدقيق Runner — DEV-073:** validatePayload ينفذ reference tests قبل productMutation ودون owner quota؛ طلب validate مكرر بنفس المفتاح يمكنه إعادة العمل المكلف قبل قراءة cache، بينما approve/publish قد يرفضان retry بمراجعة قديمة قبل replay. تقييد student submit لا يغطي هذا المسار الإداري. لم تنفذ آلية lease/quota جديدة في هذه الجولة؛ يسجلها الجذر كنقص مصدر محدد، لا إعداد Sandbox.
