# إغلاق CODE-05 وCODE-06 في المصدر

المراجع: DEV-037 وDEV-073 وDEV-077، وثيقة الامتداد `docs/19-POST-HACKATHON-DEVELOPMENT.md`، وأمر إكمال المصدر المؤرخ 2026-11-08. هذا وصف للشيفرة والفحوص الموجهة بالمحاكاة، وليس نتيجة تشغيل Judge0 أو PostgreSQL أو اعتماد عزل أو محتوى.

## نتيجة التعديل

- يمر إرسال الطالب وفحص مؤلف المحتوى واعتماده ونشره والتراجع إليه عبر `RunnerCoordinator.run` في `apps/api/src/runner-coordinator.ts`. تحفظ معاملة قصيرة حجزًا دائمًا في `runner_work_requests`؛ يجري التنفيذ الخارجي بعد إغلاقها، ثم تحفظ النتيجة وذاكرة إعادة الطلب في معاملة نهائية بعد التحقق من المالك والصلاحية والمراجعة وبصمة المحتوى. لا توجد معاملة قاعدة بيانات مفتوحة أثناء انتظار Runner.
- تسبق قراءة المفتاح وبصمة الطلب فحص المراجعة أو حالة الانتقال أو استدعاء المحرك. تعود الاستجابة المحفوظة للطلب الناجح نفسه، ويُرفض تغيير الحمولة مع المفتاح نفسه. يحافظ مسار الطالب أيضًا على رفض عرض نتيجة محفوظة تخص مراجعة قديمة. يحفظ `ProductApi` مفتاحه عند `request_in_progress`، إلى جانب حفظه عند عطل الشبكة.
- الحصص مشتركة بين الطالب والمؤلف: طلبات بالدقيقة واليوم، وعدد الحالات المحجوزة بالدقيقة واليوم، وتزامن لكل مالك وللخدمة. يحميها قفل PostgreSQL مشترك بين نسخ API. لا يستهلك replay حصة جديدة. يعيد تعارض الحصة المعاملة التحضيرية كاملة دون إنشاء محاولة أو فقد نص موجود.
- تحفظ إيصالات Judge0 الخاصة في `remote_tokens` قبل polling. لا تُسرب عبر واجهات الطالب أو نتائج مراجعة المؤلف. إذا ضاع رد POST فقد تكون المهمة مقبولة دون إيصال؛ لا يفترض المصدر أنها لم تبدأ.
- مدة الحجز 60 ثانية لحزمة Runner التي مهلة تقييمها الإجمالية 25 ثانية، و180 ثانية للتحقق الآخر المحدود بمهل المحرك. لا يعاد إرسال الحجز بعد انتهاء مدته أو إعادة تشغيل API. يُحجر العمل الغامض وسعته حتى مصالحة مشغّل مخول؛ لا يتجاوز الحجر مفتاح جديد أو مرور نافذة الحصة. تبقى الاستجابة أو رسالة الفشل المحفوظة قابلة للإعادة.
- يسبق كل إرسال حالة فحص جديد للملكية والحجز ومراجعة المحاولة؛ يقع هذا الفحص داخل مهلة التقييم ولا يرسل الكود إذا رجع الفحص بعد انقضاء المهلة. تحفظ المحاولة `queued` عند التحضير ثم تنتقل ذريًا إلى `running` قبل التنفيذ.
- تستعيد قراءة محاولة الطالب حالة انقطاع واضحة مع حفظ النص الخام، دون الكتابة على مراجعة أحدث. تؤجل دالة الاحتفاظ محو أصحاب الحجوزات الجارية أو المحجورة، وتستخدم القفل المشترك؛ بعد المصالحة تتبع السجلات سياسة المحو القائمة. الترحيل `0018_durable_runner_work` ملف مراجعة لم ينفذ.

## نتائج المعلم الخاصة

يعيد `ContentValidation.programming` الإجماليات العلنية والمخفية وقائمة حالات مرقمة: `visibility/status/passed/executed`. يوضح تمييز `executed=false` أن الحالة لم تنفذ، ولا يحسبها نجاحًا. يستمر فحص المرجع في بقية الحالات بعد خطأ تنفيذ معلوم، ويتوقف عند فقد اليقين بالخدمة. لا تتضمن هذه التفاصيل مدخلات أو إجابات أو stdout أو stderr.

يحفظ `ContentStudioService.validatePayload` هذه النتيجة ضمن تحقق النسخة، وتفك الواجهة عقدها وتعرضها في جدول للمؤلف والمراجع. يبقى مسار إرسال المسودة مربوطًا بفحص `/validate` قبل الانتقال إلى المراجعة. يمنع النشر ما لم يجتز الحل المرجعي كل الحالات. يعرض `ProgrammingService.submit` إسقاطًا صريحًا لحقول الطالب السابقة؛ لا ينسخ حقول نتائج المؤلف أو حالة عدم اليقين الداخلية إلى `ProgrammingResult`.

## الأدلة والفحوص

المصدر: `apps/api/src/runner-coordinator.ts`، `apps/api/src/programming-runner.ts`، `apps/api/src/programming.ts`، `apps/api/src/content-studio.ts`، `apps/web/src/ContentStudio.tsx`، `apps/web/src/product-api.ts`، وترحيل 0018 ونموذج Prisma المقابل. توثيق الحصص والمصالحة في `ops/BETA-RUNBOOK.md` وإعداداتها المثال.

الفحوص الموجهة: `apps/api/tests/runner-coordinator.test.mjs` يحاكي معاملات متسلسلة قابلة للتراجع وخدمة Runner؛ يغطي replay قبل المراجعة، اختلاف الحمولة، التزامن والحصص المشتركة، انتهاء الحجز وإعادة إنشاء المنسق، حظر تجاوز الحجر بمفتاح جديد، حفظ الإيصال قبل polling، خصوصية النتائج، فحص المؤلف وانتقاله الفعليين، رفض التحقق المتأخر، وحفظ نص الطالب وإسقاط حقوله. أضيف فحص مفتاح العميل إلى `apps/web/tests/product-experience.test.mjs`. لا تعادل محاكاة المعاملات اختبار سباق PostgreSQL فعليًا.

نتائج الأوامر النهائية تسجل بعد تجميد المصدر في تقرير القبول الرئيسي. لا اختبارات تحميل أو migrations أو تشغيل خدمة أو Runner أو اتصالات خارجية ضمن هذه الفحوص.

## أعمال تشغيلية لاحقة

تطبيق الترحيل على قاعدة اختبار ومراجعة فهارسه وقيوده وصلاحياته، تجربة تنافس عدة نسخ API وانقطاع العملية قبل/بعد POST وقبل/بعد commit، التحقق من ربط الضيف والمحو، إعداد Runner محصن وإثبات منع الشبكة والملفات وتحديد الموارد، تجربة مصالحة مهمة محجورة، ومراجعة المحتوى ونشره يدويًا. المصدر لا يزعم استئناف العمل المعزول تلقائيًا أو exactly-once لدى Judge0 عند فقد رد قبول المهمة.
